# StockOracle 구조·예측·모멘텀 전략 감사 및 개선 보고서

검토일: 2026-10-09 (한국시간). 기존 작업 트리의 수정·미추적 파일·삭제 상태를 보존했다. 이번 변경은 별도 커밋·배포·매매 실행 없이 작업 트리에 적용했다. 기존 감사 문서의 성능 수치는 이번 작업의 새 측정값으로 취급하지 않는다.

## ① 요약

[사실] 한국·미국 주식 분석 API, 규칙 점수, ML 추론, 변동성 기반 가격 시나리오, 전략 스캔, 오프라인 평가의 전체 연결 구조를 검토했다. 이번에는 재현 가능한 모멘텀 판정·장중 봉·스캔 캐시·학습 분할·평가·모델 저장 결함을 수정했다. 기존 503개 테스트가 통과하더라도 이 경계 조건은 별도 테스트가 필요했다.

[데이터 불확실] 영상 원문은 접근 제한으로 확인하지 못했다. 구현 기준은 사용자가 제공한 설명이다. 종가 기준인지 장중 저가 기준인지, 손절·익절·주문 유형은 영상에서 직접 확인하지 못했다. 종가 판정을 기본으로 유지하고 저가 이탈을 별도 참고값으로 반환한다.

[사실] 52개 캐시 파일에서 급등 사건 95개, PASS 76개·FAIL 19개를 재평가했다. 다음 거래일 시가 진입, 왕복 비용 가정 KRX 0.2%·US 0.1%, 추가 슬리피지 0%에서 PASS의 5일 평균 순수익률은 약 +0.055%, 순수익 양수 비율은 40.79%였다. 진입 슬리피지 1% 시 5일 평균 순수익률은 −0.937%, 양수 비율은 36.84%로 바뀌었다. 이는 사건 연구이며 포트폴리오 성과나 확정 예측 정확도가 아니다.

## ② 문제 재정의

목표를 '신호를 더 많이 만들기'가 아니라 '같은 정보 시점에서 재현 가능한 판정·예측·검증을 제공하기'로 정의했다. 프로젝트가 한국·미국 전 종목을 매 요청마다 전수 검색한다는 전제는 맞지 않는다. API 스캔은 구성된 유니버스 또는 전달된 종목 목록에 수집 상한을 적용한다. 따라서 '20% 급등한 모든 종목'은 현재 검사한 유니버스 안의 조건 충족 종목이라는 의미다. 시장 전체 검색에는 별도 종목 마스터와 배치 작업이 필요하다.

신호 정의는 전일 종가 B, 급등일 종가 S, 관찰 종가 C1·C2·C3에 대해 S/B−1 ≥ 0.20, 유지선 M=B+0.5(S−B), 각 Ck ≥ M이다. B=100, S=120이면 유지선은 110이다. 120의 절반인 60이나 고점 대비 50% 하락을 뜻하지 않는다. 급등일은 관찰 3일에 포함하지 않는다. 확정된 3거래일을 확인한 다음 실제 주문 가능한 거래일부터 진입을 평가한다.

## ③ 분석

### 시스템 지도와 적용 프레임워크

PR → MDA → IA·반증 → CS 순서로 분석했다. 이 프레임워크들은 감사 질문을 구조화하는 도구이며 수치화된 과학 법칙으로 사용하지 않았다. PR은 사용자의 가치가 '정확한 매수 타이밍과 예측'인지 '많은 후보'인지 분리하기 위해 선택했다. 원인 수준을 화면의 신호 개수에서 입력 데이터의 확정 시점과 평가 표본으로 옮겼다. 가정은 설명된 20%·3거래일·절반 유지가 기본 규칙이라는 것이며, 한계는 영상의 주문·손절 세부 규칙을 확인하지 못한 점이다. 따라서 추가 필터를 원래 전략의 필수 조건으로 임의 삽입하지 않았다.

MDA는 시간·시장·가격 단위·계층을 함께 보기 위해 적용했다. 시간 차원에서는 실시간 현재가, 진행 중 일봉, 확정 일봉, 미래 라벨 확정일이 서로 다른 정보라는 점이 핵심이다. 시장 차원에서는 KRX와 미국의 시간대·휴장일·지수 프록시가 다르다. 계층 차원에서는 데이터 수집이 정상이어도 전략 판정이나 화면 승격에서 오류가 생길 수 있다. 중요도는 실제 진입 상태에 영향을 주는 오류와 학습 누수에 높게 두었다. 외부 공급자의 최신 데이터가 정확하다는 가정을 두지 않았으며, 캐시 평가만으로 실시간 공급자의 품질을 입증할 수 없다는 제약을 명시했다.

IA와 반증은 기존 503개 테스트 통과라는 초기 근거를 그대로 신뢰하지 않고 경계 입력으로 깨뜨리기 위해 사용했다. 정확히 100→120인 입력은 부동소수점 표현 때문에 20% 문턱에서 누락될 수 있었다. 중간의 결측 가격을 삭제하면 이틀 이상에 걸친 상승이 하루 급등으로 둔갑할 수 있었다. 3일차 장중 가격을 넣으면 확정되지 않은 종가로 PASS가 나왔다. PASS 후 현재가가 유지선 아래로 붕괴해도 READY 승격이 가능했다. 각 사례는 단순히 유망한 가설이 아니라 합성 입력으로 재현하고 회귀 테스트로 고정했다. 단, 합성 테스트는 거래 수익성을 입증하는 근거로 사용하지 않았다.

CS는 구조를 전면 교체하기보다 효과가 크고 영향 범위를 검증할 수 있는 경계를 고르기 위해 적용했다. 3만 줄에 가까운 API 파일에는 라우팅, HTML·JavaScript, 지표 계산, 예측 폴백, 수집·캐시가 함께 있다. 한 번에 모두 분리하면 기존 계약을 깨뜨릴 위험이 크다. 이번에는 독립 계산 모듈과 연결 지점의 입력·출력을 바로잡았다. 한계는 모든 분기의 외부 서비스 장애를 이번 오프라인 검증에서 실행하지 못했다는 점이다. 따라서 '전체 시스템의 모든 오류 제거'라고 결론 내리지 않는다.

### 반증·인과·리스크 재평가

[낮은 확실성] 급등 뒤 하락을 견딘 가격은 수요의 지속과 양립하지만, 가격만으로 매수 주체·원인·정보 우위를 확인할 수는 없다. 유동성 부족, 거래정지, 기업행사, 특정 상승장도 같은 패턴을 만들 수 있다. 이 전략을 수요의 인과적 증거로 표시하지 않는다. 필요한 데이터는 체결·호가·유통주식·공시·분할·거래정지 이력과 당시의 상장 종목 전체 목록이다.

[사실] 재평가의 전체 PASS 5일 평균 순수익률은 거의 0이며 FAIL 5일 평균보다 낮다. 10일·20일에서는 PASS 평균이 더 높지만 표본이 76개로 작고 종목·날짜·사건이 겹친다. 상폐·급락 종목이 빠진 생존 편향과 시장 환경의 영향을 분리하지 않았다. 평균이 양수라는 사실만으로 전략의 일반적 수익 우위나 실시간 적중률을 인정할 수 없다. 점수·방향 확률에 새 보너스를 넣지 않았고 기존 READY 승격 기본값은 유지하되 연구 신호라는 설명과 현재 진입 조건을 일치시켰다.

## ④ 분석 기반 고도화 아이디어

아래는 이번 수정 외의 후속 설계 제안이다. 적용 완료로 표시하지 않는다. 최소한의 테스트로 신뢰성을 검증한 뒤 운영 설정·데이터·비용에 맞춰 선택해야 한다.

1. **시장 전체 배치 스캔과 웹 조회 분리.** 현재 API의 종목 상한은 서버리스 시간 예산에 대응하는 장치다. 이를 단순히 늘리는 대신 거래소 종목 마스터를 날짜별로 저장하고, 배치가 모든 종목의 확정 일봉을 갱신한 뒤 전략 상태를 계산하도록 구성한다. 웹 요청은 완료된 결과와 생성 시각을 조회한다. 성공 기준은 해당 날짜 상장 종목 대비 수집률, 실패·제외 종목 수, 마지막 완료 시각이다. 이 구조가 있어야 '모든 급등 종목'이라는 요구의 누락 범위를 정량적으로 설명할 수 있고, 느린 외부 요청이 사용자 응답을 중단하는 문제도 줄일 수 있다.

2. **일봉 확정·출처 계약 확대.** 각 데이터 행에 거래소 현지 거래일, 수집 시각, 원천, 조정주가 여부, 확정 여부를 보존한다. 현재 날짜 판정은 정상적인 일봉 공급자를 가정하며 조기 폐장·공급 지연에는 한계가 있다. 거래소 달력의 실제 종료 시각과 공급자 확정 플래그를 결합해 일봉의 신뢰 상태를 만들 수 있다. 단, 진행 중 가격을 버리면 실시간 화면의 효용이 줄 수 있으므로 화면 현재가와 전략 판정용 확정 종가를 함께 보여준다. 검증은 정상장·휴장·서머타임 전환·미국 조기 폐장·마감 직후 지연 데이터 사례로 수행한다.

3. **기업행사로 인한 가짜 급등 차단.** 분할·병합·배당·스핀오프와 종목 변경 이력을 사건 날짜에 맞춰 기록한다. 하루 20% 움직임을 찾기 전에 양일 가격의 조정 방식이 같은지 검사하고, 불일치하면 급등으로 확정하지 않는다. 조정주가는 장기 수익률 연구에 적합하지만 실제 주문 가격과 단위가 다를 수 있어 시가·손절·주식수 계산에는 변환 정보가 필요하다. 성공 기준은 알려진 기업행사 테스트에서 허위 급등이 나오지 않고 실제 경제적 급등은 유지되는 것이다. 공급자 간 가격이 다르면 평균으로 덮기보다 출처 차이를 명시한다.

4. **종가 전략과 저가 전략을 별도 비교.** 기본 종가 조건과 엄격한 저가 조건은 다른 전략이다. 저가 이탈을 표시하는 것을 넘어 각 전략의 사건 수·다음 시가 수익률·낙폭·비용 민감도를 동일 기간에서 비교한다. 저가 조건이 사건을 줄여도 수익성이 높아진다고 자동 가정하지 않는다. 임계값은 검증 기간에서 반복 조정하지 않고 개발 기간에서 선정한 뒤 미사용 기간에서 한 번 평가한다. 추가로 거래량 배수 조건을 켠 집단과 끈 집단을 비교해 효과가 가격 조건과 독립적인지도 확인한다. 표본이 부족하면 설정을 추천하지 않고 부족한 사건 수를 보고한다.

5. **주문과 체결을 반영한 거래 시뮬레이터.** 이번 백테스트는 사건 이후의 수익률 연구이고 손절 주문을 실행하지 않는다. 후속 단계에서는 다음 시가 갭, 지정가 미체결, 거래정지, 가격제한, 일봉 내 손절·목표 동시 도달의 순서 불명확성을 처리한다. 일봉만 있다면 유리한 순서를 선택하지 않고 보수적 시나리오와 낙관적 시나리오를 둘 다 기록한다. 체결 모형은 거래소·유동성 구간별로 따로 설정하며 비용을 실제 세율이라고 단정하지 않는다. 성공 기준은 모든 거래가 신호 확정 뒤에 발생하고 불가능한 가격에서 매수·매도가 일어나지 않는 것이다.

6. **중첩 사건과 포트폴리오 위험 관리.** 연속 급등하는 한 종목에서 여러 사건이 나오면 사건별 평균은 실제 동시에 보유 가능한 자금의 성과와 다르다. 종목별 포지션 한 개, 최대 동시 보유 수, 시장별 노출, 동일 산업 비중, 현금 제약을 정한 뒤 포트폴리오 순자산을 계산한다. 동일 종목의 연속 신호를 새 거래로 볼지 관찰 상태 갱신으로 볼지도 명시한다. 성공 기준은 현금·주식수·리스크 예산이 항상 일치하고 레버리지 없는 설정에서 구매액이 가용 자금을 넘지 않는 것이다. 이 검증 뒤에만 사건 평균을 연간 수익률이나 운용 성과로 확장할 수 있다.

7. **시간을 고정한 독립 평가셋.** 기존 개발 과정에서 여러 후보와 기준을 비교한 홀드아웃은 완전히 독립적이라고 보기 어렵다. 새 수정 이후의 기간을 봉인된 평가 구간으로 지정하고, 임계값·특징·모델 선택을 그 기간에 맞춰 바꾸지 않는다. 선택 단계는 내부 walk-forward로 수행하고 마지막 평가는 한 번만 공개한다. 종목·월 단위 블록 재표본화로 겹친 관측의 신뢰구간을 계산하면 단순 사건 수에서 오는 과신도 줄일 수 있다. 성공 기준은 단순 기준모형 대비 개선과 그 불확실성을 같은 표본에서 보고하는 것이며, 개선이 없으면 신호 가중을 유지하거나 낮춘다.

8. **가격 범위와 방향 예측의 품질 분리.** 가격 분포가 넓어지면 포함률은 좋아져도 투자 판단이 더 유용해진다고 단정할 수 없다. 방향에는 AUC·Brier·보정 곡선을, 범위에는 명목 포함률·폭·분위 손실·음의 로그우도를, 목표 도달에는 실제 고저가 터치율을 사용한다. 같은 기준가·정보 시점·예측 기간으로 각 지표를 계산해야 화면 간 모순을 추적할 수 있다. 검증은 한국·미국, 상승·하락·횡보장, 변동성 구간별로 나눈다. 성능을 하나의 '정확도' 숫자로 합치지 않으면 모델이 잘하는 것과 못하는 것을 사용자가 구체적으로 이해할 수 있다.

9. **학습 특징의 출처·버전 고정.** 현재 특징 이름에는 레거시 시장 슬롯이 남아 있으며 실제 소스는 한국·미국으로 재해석된다. 특징 이름뿐 아니라 지수 프록시·가격 조정·계산 창·결측 처리·라벨 기간·출처 정보까지 스키마 버전에 포함한다. 모델 저장 시 이 스키마의 해시를 기록하고 추론에서 일치 여부를 확인한다. ^KS11에서 ETF로 대체된 날짜도 기록해야 기준지수 변경의 영향을 별도로 평가할 수 있다. 성공 기준은 모델과 추론 특징의 불일치 시 조용히 예측하지 않고 명시적으로 사용 불가를 반환하는 것이다. 기존 모델은 별도 재검증 후 새 버전으로 전환한다.

10. **모델 아티팩트의 원자적 발행.** 이번 저장 게이트는 검증 실패 모델을 막지만, 모델·특징 목록·메타데이터를 여러 파일로 순차 저장하는 중 프로세스가 중단되면 서로 다른 버전이 남을 수 있다. 후속으로 버전 디렉터리에 전체 파일을 저장하고 해시·로딩 검증이 끝난 뒤 활성 버전 포인터만 원자적으로 교체한다. 이전 버전을 유지해 빠르게 복구하며 실험 모델은 별도 경로로 저장한다. 성공 기준은 저장 중 장애를 주입해도 운영 추론이 이전의 완전한 모델이나 새 완전한 모델 중 하나만 읽는 것이다. 이는 예측 정확도 개선보다 배포의 일관성을 보장하는 조치다.

11. **API 분리와 계약 중심 회귀 검증.** 거대한 api/index.py에서 수집·전략·예측·직렬화·화면 템플릿을 순차적으로 추출한다. 먼저 현재 JSON 응답과 화면에서 소비하는 필드를 계약으로 고정하고, 작은 모듈을 하나씩 바꾸면서 같은 입력의 응답 차이를 비교한다. 서버 폴백과 패키지 구현의 중복도 이 과정에서 줄일 수 있다. 다만 모든 코드를 동시에 이동하면 기존 예외 경로가 사라질 위험이 있으므로 독립 계산부터 진행한다. 성공 기준은 온라인·오프라인 경로가 같은 신호 정의와 가격 기준을 사용하며, 외부 API 실패가 부분 데이터 상태로 명확히 나타나는 것이다.

12. **관측성과 판단 보류 상태 강화.** 캐시 hit 여부, 데이터 마지막 날짜, 스캔 수집률, 모델 사용 여부, 검증 근거, 전략 확정 시각을 응답과 로그에 기록한다. 데이터가 부족하거나 오래되면 매수·매도 문구 대신 판단 보류와 부족한 항목을 표시한다. 점수·확률·신호 신뢰도의 의미를 구분해 같은 가격 움직임을 여러 번 가산하는 것을 막는다. 경고가 너무 많으면 중요한 결함을 놓치므로 데이터 누수·미확정 봉·체결 불가능·필수 가격 결측을 우선 표시한다. 성공 기준은 사용자가 PASS 발생 이유뿐 아니라 현재 READY로 승격되지 않는 이유도 데이터 근거로 이해할 수 있는 것이다.

## ⑦ 추가 탐색 포인트 및 자체 평가

우선순위는 시장 전체 당시 유니버스·기업행사 출처, 실현 체결·손절 시뮬레이션, 새 규칙으로 재학습한 모델의 미사용 기간 평가다. 미국 조기 폐장, 외부 API 장애, 서버리스 제한 안의 실제 응답시간도 온라인 검증이 필요하다.

자체 평가(각 1~5, 평균 4.0): 정확성 4—테스트·캐시 재현으로 코드 결함은 확인했지만 영상·온라인 데이터는 미확인; 완전성 4—구조와 핵심 경계 수정 완료, 전 종목·모든 외부 장애 경로 미검증; 명확성 4—적용 수정과 후속 아이디어를 분리했으나 API 구조가 여전히 큼; 실행성 4—코드·명령·테스트·보고서 제공, 배포·재학습은 미수행; 간결성 4—사용자 요구에 맞춰 상세 문서화했지만 전체 보고서는 길다. 사용자가 동의할 수 있도록 주장마다 확인 범위와 미검증 항목을 밝혔다. 개선 우선순위는 새로운 독립 평가와 체결 검증이다.
