# StockOracle 구조·예측 경로 점검 (2026-09-20)

## 범위와 기준

현재 작업 트리의 코드와 문서를 기준으로 점검했다. 작업 시작 시 이미 다수의 미커밋 변경이 있었으므로 이 보고서는 기준 커밋의 상태가 아닌 현재 코드의 동작을 설명한다. 가격 예측의 통계적 적중률을 새로 검증한 보고서는 아니다.

## 시스템 지도

| 계층 | 파일/디렉터리 | 역할과 경계 |
|---|---|---|
| 배포 | `vercel.json` | 모든 경로를 서버리스 `api/index.py`로 연결하고 실행 시간·메모리를 지정한다. |
| HTTP·화면 | `api/index.py` | 종목 식별, 일봉 수집, 지표, 진입·손절·목표, 예측 조합, API 응답, 인라인 HTML/CSS/JS를 한 파일에서 담당한다. |
| 시세 | `us_price_fetcher.py`, `market_briefing/data_fetcher.py` | 미국 세션별 시세와 한국·미국 시장/거시 데이터 수집 및 폴백을 담당한다. |
| 분석 | `market_briefing/` | 동적 RSI, 신호 신뢰도, 패턴, 펀더멘털, 업종, 뉴스, 상관성, 변동성 예측, ML 보조 신호를 분리한다. |
| 모델·검증 | `models/`, `scripts/`, `datasets/`, `docs/backtests/` | 학습 산출물, 오프라인 백테스트, 학습 데이터와 과거 평가 결과를 보관한다. |
| 실행·회귀 | `dev_server.py`, `tests/` | 로컬 HTTP 서버와 계산·응답·화면 회귀 검증을 제공한다. |

요청 흐름은 `GET /api/stock` → 종목 식별 → 가격 이력·실시간 시세 수집 → 지표와 매수/리스크 계산 → `build_prediction_outlook` → `prediction_outlook`/`buy_price`/`risk_scenarios`를 함께 JSON 반환 → `renderForecast` 순서다. 차트·지표 이력은 1년 일봉 고정이며 예측 기간은 별도 설정이다. `prediction_outlook.forecast`는 변동성 기반 가격 범위이고 LightGBM은 별도 보조 신호다.

## 분석 방법과 발견

1. **문제 재정의(PR)**: “예측 탭이 비거나 부족하다”를 공급자 응답 실패, 서버 계산 결측, JSON 계약, 화면 표시라는 네 층으로 나눴다. 이유는 같은 빈 화면이라도 수정 위치가 다르기 때문이다. 전제는 실제 사용자가 종목 상세 분석을 요청한다는 것이며, 배포된 운영 환경과 로컬 외부 공급자의 상태가 같다는 보장은 없다.
2. **다차원 분석(MDA)**: 시간(최신 봉 vs 과거 봉), 시장(KRX vs US), 계층(Python vs JS), 근거(실제 관측 vs 대체 추정)를 비교했다. 최신 RSI/MACD/이동평균 결측이 이전 날 값으로 대체되면 현재 상태가 잘못 보였고, 종가 결측을 삭제하면 서로 떨어진 두 봉을 하루 수익률로 연결했다. KRX 실제 호출에서는 외국인·기관 수급 수집이 실패했으나 가격 예측과 리스크 세 시나리오는 생성됐다. 이는 공급자 공백을 사용자에게 명시해야 하는 근거다.
3. **복잡성 해결(CS)**: 2만 줄이 넘는 단일 `api/index.py`를 전면 분리하기보다 예측 경로의 입력 정렬, 결측 게이트, 화면 폴백을 좁게 고쳤다. 이 순서는 공통 데이터층의 오류가 여러 카드로 증폭되는 것을 먼저 막는다. 제약은 기존의 미커밋 변경과 공개 API 계약을 보존해야 한다는 점이다.

관찰된 결함은 다음과 같다. 최신 봉의 지표가 비면 `build_prediction_outlook._last`가 해당 열의 마지막 **과거 유효값**을 가져와 현재 RSI·MACD·이동평균처럼 표시했다. `daily_log_volatility`는 결측 종가를 삭제하여 공백 양쪽 가격을 한 거래일 수익률로 계산했다. 브라우저는 `Number(null) === 0` 때문에 미산정 RSI·목표 도달 가능성·기간을 0으로 표시했다. 이전 종목의 리스크 응답이 없는 경우 리스크 그리드가 갱신되지 않아 낡은 카드가 남을 수 있었다. README와 `prediction_output_contract.json`도 현행 계산법과 필드 이름이 달랐다.

반증도 확인했다. 기존 OHLCV 공통 행 정렬과 최종 JSON의 `NaN`/`Infinity` 정리는 이미 구현돼 있었다. 과거 인계 문서의 해당 결함을 다시 수정하지 않았다. 초기 283개 테스트가 모두 통과했으므로 기존 테스트만으로 위 결측 표시 문제를 발견할 수 없었다.

## 적용 결과

- 최신 유효 종가와 **같은 행**에서 지표를 읽고, 그 행의 지표가 없으면 미확보로 처리한다. MA20·MA60 결측은 예측 신뢰도 감점과 데이터 공백 설명에 반영한다.
- 변동성 계산은 최근 61개 일봉 위치를 유지하고 유효한 인접 쌍에서만 로그수익률을 만든다. 패키지 함수와 서버의 최후 폴백에 동일한 결측 규칙을 적용한다.
- 예측 탭에 마지막 일봉 날짜, 이력 길이, 출처, 품질 상태 및 주요 경고를 표시한다. 미산정 값은 `미확보`·`미산정`·`산정 보류`로 표시하고, 리스크 응답이 없을 때 오래된 카드를 지운다.
- README와 예측 응답 계약을 현행 1년 이력, 변동성 가격 범위, nullable 필드에 맞췄다.

## 검증과 한계

전체 단위/회귀 테스트 287개와 인라인 JavaScript 구문 검사를 통과했다. 새 회귀 검사는 지표 결측, 이동평균 결측, 가격 공백, 브라우저의 미산정 표시와 이전 카드 제거를 재현한다. 실제 데이터 경로에서 `AAPL`은 품질 정상·예측 `ok`·시나리오 3개·리스크 프로필 3개였고, `005930.KS`는 예측 `ok`·시나리오 3개·리스크 프로필 3개였다. KRX 응답의 데이터 상태는 `일부 데이터 수집 실패`였으며 실패 항목은 `investor_flow`였다. 두 요청은 로컬에서 실행했으며 운영 배포 검증이나 예측 수익률 검증을 뜻하지 않는다.

## 다음 개선 후보

1. 거대한 `api/index.py`의 HTTP, HTML, 계산을 단계적으로 분리하고 함수별 입력/출력 계약을 코드로 검증한다.
2. 시세 공급자별 `as_of`, 지연 시간, 실패 원인을 응답에 표준화하여 가격의 최신성을 직접 비교한다.
3. KRX 수급 공급자 장애의 폴백과 재시도 제한을 분리하고 실패 시 사용자에게 수급 미반영을 명시한다.
4. 신규 상장·거래정지·분할 종목을 별도 품질 등급으로 관리하고 일정 표본 이하에서는 수치보다 관찰 상태를 우선한다.
5. 예측 구간의 실제 포함률과 목표가의 손절 우선 도달률을 KRX/US·시가총액·변동성 버킷별로 지속 측정한다.
6. 시나리오 비중·신호 신뢰도·실현 확률의 명칭과 검증 데이터를 분리하여 확률 오해를 줄인다.
7. 현재가 보정 직후 차트 마지막 봉, ATR, 목표·손절 가격의 기준 시각을 일치시킨다.
8. API 응답 스키마 검증을 CI에 넣어 백엔드 필드 변경이 탭 공백으로 이어지지 않게 한다.
9. 브라우저 렌더링을 실제 DOM 기반 테스트에서도 검증하여 HTML 삽입과 탭 전환 시 오류를 조기에 잡는다.
10. 모델 검증 메타데이터의 홀드아웃·시계열 분리 결과를 주기적으로 갱신하고 열화 시 보조 모델 가중치를 낮춘다.
