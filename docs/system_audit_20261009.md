# 구조 감사 — 허스트·장중 거래량·ML 가중·변동성·미국 장기 추천 (2026-10-09)

요청: 스크립트 전체 구조를 먼저 분석하고, 정상 동작하는 기능은 보존한 채 **중복·충돌·종속**을 근거로 결함을 고쳐 예측 체인을
고도화할 것(조건을 임의로 더하거나 무조건 강화하지 말 것). 이전 감사(10-08 예측 체인, 10-09 매수 구간·방향 확률 보정)가 다룬
부분은 다시 만지지 않고, 그 문서가 "남은 충돌"로 적은 항목과 아직 검증되지 않은 층을 대상으로 했다.

## 한눈에

- 새로 확인한 결함은 **6건**이고 모두 코드·측정으로 재현했다. 조건·임계값을 새로 추가한 것은 없다.
  수정은 ① 값을 잘못 계산하던 함수 교정(허스트), ② 조회 시각에 따라 흔들리던 입력의 기준 통일(장중 거래량), ③ 근거가 낙관적이던
  가중치 입력 교정(ML), ④ 측정으로 더 나은 추정기로 교체(변동성 σ), ⑤ 같은 근거를 두 번 세던 합산 제거(진단 배지),
  ⑥ 깨져 있던 연결 복구(미국 장기 추천)다.
- **방향 예측력은 이번에도 늘지 않았다**(방향 확률 AUC 0.51 그대로, 퇴보도 없음). 늘어난 것은 확률·범위가 *무엇을 말하는지*의 정직성과
  변동성 범위의 보정이다: P10~P90 포함률 79.2% → **81.3%**, P05~P95 88.2% → **89.8%**(명목 80/90%).
- 허스트·ML 가중·변동성 비중은 환경변수로 즉시 되돌릴 수 있다(맨 아래 표).
- 테스트 425개 → **457개** 통과, 인라인 JavaScript 구문 검사 통과, 개발 서버에서 `/api/stock`(AAPL, MSFT)·`/api/us/longterm` 실호출 확인.

## 시스템 지도 — 같은 개념이 몇 번, 어디에서 계산되는가

요청 흐름은 이전 문서와 같다: `GET /api/stock` → 종목 해석 → 일봉·실시간 시세 → 지표 → 점수(`analyze_score`·`finalize_rule_score`) →
확률(`calc_probability` → ML 블렌드 → 상관 엔진 → 보정) → 매수 구간·목표가·리스크 → `build_prediction_outlook` → JSON → 브라우저 렌더.

| 개념 | 구현 위치 | 이번 판정 |
|---|---|---|

## 절충과 결정

- **매수 단계 도달 확률은 Brier 가 0.0005~0.0014 소폭 나빠졌다**(AUC 는 소폭 좋아짐). 1·2차 구간은 모두 *아래쪽 가격*의 터치만 평가하고,
  표본이 상승 구간이라 무추세 모형이 하락 방향 터치를 원래 과대 예측한다(이전 문서의 알려진 한계). σ 가 커지면 그 과대가 조금 더 커진다.
  상·하 대칭 수준(현재가 ±0.5~2.0σ√30)으로 평가하면 터치 Brier 가 0.1646 → 0.1636 으로 오히려 좋아지고 평균 편향이 −1.4%p → +0.5%p 로 0에 가까워진다.
  종료 분포(예측 범위) 개선이 더 크고 일관돼 그대로 두되, 표본에 맞춘 드리프트 상수는 넣지 않았다(이전 결정 유지). 불리하게 느껴지면 `STOCKORACLE_VOL_LONG_RUN_WEIGHT=0`.
- **ML 은 이제 확률·상관 투표에 반영되지 않는다**(가중 0). 기능을 지운 것이 아니라 기존 규칙("검증 AUC < 0.52 면 가중 0")을 더 보수적인 근거에 적용한 결과다.
  ML 예측은 응답의 `ml_prediction` 에 그대로 남는다. 이전 동작을 원하면 `STOCKORACLE_ML_AUC_BASIS=holdout`(가중 15%).
- **진행 중 막대는 보간하지 않는다.** 장중 누적 거래량을 시간대 곡선으로 부풀리면 곡선 가정(오프라인으로 검증 불가)이 새로 생긴다. 직전 확정 막대 기준은 하루 묵었지만 편향이 없다.
  거래량 *급증* 판정은 부분값도 하한이라 유효하지만, 캔들 방향과 같은 막대로 짝을 맞추려고 두 값을 함께 옮겼다.
