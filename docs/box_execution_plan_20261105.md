## 3. 수정 사항

### `box_sequence.py` — 박스 계단 검출

- Darvas 3봉 규칙을 상승·하락 양방향으로 적용하는 상태 기계. 형성 중 범위가 6 ATR를 넘으면 추세 구간으로 보고 최신 극점에서 다시 시작.
- 종가가 박스 경계를 0.1 ATR 넘게 벗어나면 그 박스는 끝(`exit` up/down)나고 새 박스 형성.
- 박스끼리 비교(`relation`: 위·아래·겹침)와 계단 요약(`staircase`: 하락 계단 / 하락 후 안 빠지는 박스 / 하락→상승 전환 / 상승 계단 / 횡보).
- 완료 일봉만 받는다(진행 중 봉 제외는 `apply_box_prediction`). 확정된 과거 박스는 이후 봉이 추가돼도 바뀌지 않음(테스트).
- 35% 넘는 하루 종가 급변은 수정주가 미반영 의심으로 기록.
- 검출률: 3,560 시점 중 87%에서 현재 박스 확정(기존 엔진 약 16%). 박스 높이 중앙값 3.0 ATR, 기간 중앙값 14봉.

### `box_plan.py` — 결정 계층

판정 5종과 단계 6종을 분리했다.

| 판정 | 뜻 | 단계 |
|---|---|---|
| 🟢 매수 | 가격·신호·위험 조건 모두 충족 | 신호 확인 완료 |
| 🟡 조건부 매수 | 계획은 유효, 가격 또는 종가 확인 대기 | 가격 도달 대기 / 가격 도달 · 신호 확인 중 |
| 🟠 관망 | 매수 조건 미충족(하락 박스, 상단 바로 아래, 좁은 박스 등) | 조건 미충족 |
| 🔴 매수 제외 | 박스 하단 이탈·돌파 실패 | 계획 취소 |
| ⚪ 산출 불가 | 데이터 부족·지연·불일치 | 산출 불가 |

전략 선택(롱 전용):

- **하단 지지 매수**: 박스가 직전 박스보다 낮지 않을 때만(영상: 하락 박스 하단은 매수 자리 아님). 매수 구간 = 하단 ~ 하단 + min(높이 25%, 0.5 ATR), 신호 = 직전 완료 일봉이 구간까지 내려왔다가 하단 위·전일보다 높게 마감. 손절 = 하단 − 0.35 ATR, 목표 = 박스 중간 → 박스 상단. 박스 높이 2.5 ATR 미만이거나 최종 손익비 1:1 미만이면 제외.
- **상단 돌파 → 돌파 후 재확인 매수**: 종가 상단 + 0.1 ATR 이상 2회 = 돌파 확인. 매수 구간 = 깨진 상단 ~ 상단 + 0.5 ATR, 신호 = 확인 뒤 그 구간까지 눌렸다가 상단 위 마감. 손절 = 상단 − 0.6 ATR(영상: 실패해 되돌아오면 손절). 목표 = 상단 + 높이 50% → 상단 + 높이 100%(측정 이동). 이전 박스 경계가 사이에 있으면 목표가 아니라 경고로 표시.
- **관망·매수 제외**: 하락 박스 안, 상단 근처(돌파 전), 측정 목표를 이미 넘긴 경우, 하단 이탈, 돌파 실패.
- 장중 현재가와 완료 일봉이 엇갈리는 경우(완료 종가는 이탈인데 현재가는 회복, 또는 돌파 후 장중 손절가 아래)는 매수가 아니라 "종가 확인 중"으로 표시.
- 서비스 종합 판단이 `caution`(구조 이탈·이벤트·붕괴 대기)이면 `매수`를 `조건부`로 낮춤. 실적 D-5 이내는 경고.
- 가격은 호가 단위로 맞춤(매수 하단 올림·상단 내림, 손절·목표 내림). KRX는 2023-01-25 통일 호가표(코스닥 포함 20만~50만 500원, 50만 이상 1,000원), 미국은 $0.01($1 미만 $0.0001).
- 대기 기간은 프로젝트의 무추세 터치 모델(`forecast_model.touch_probability_range`·`touch_time_window`)로 "5·20거래일 안에 닿을 가능성"과 "닿는다면 몇 거래일째"만 제시하고, 방향 예측이 아니라고 명시. 박스 확정·종가 확인처럼 가격이 아닌 조건은 "예측하지 않음 — 조건으로 확인"으로 표시.
- 데이터 검증: 마지막 완료 일봉이 10일 넘게 지났거나, 현재가가 마지막 종가와 35% 넘게 다르거나, 박스 구간 안에 35% 급변이 있으면 가격을 만들지 않음.

### 8.2 "플랜 완성"의 정의와 선정

`market_briefing/scan_box_plan.py`가 예측 탭과 **같은** `box_plan.build_execution_plan` 결과에서 다섯 항목을 읽는다(값이 두 화면에서 어긋날 수 없다). 완성 조건은 모두 만족:

1. 1차 목표 = 역할 `box_mid`, 2차 목표 = 역할 `box_top` (`box_plan._targets` 가 목표마다 `role` 을 붙이도록 바꿨고 라벨 문자열을 파싱하지 않는다)
2. 손절 기준 가격(없으면 보유자 손절)
3. 재진입 후보 구간(저·고)
4. 예상 기간(`timing` 에서 최소 대기 봉 수·가격 도달 거래일 중 하나라도 말할 수 있을 것)
5. (§8.7, 2026-11-07 3차 요청) 1차·2차 목표가 표의 현재가보다 **엄격히 높을 것** — 아니면 `target_mid_passed` / `target_top_passed` 로 제외
6. (§8.9, 2026-11-07 5차 요청) 3차 목표(중립적 TP2 고가)가 **2차 목표보다 높을 것** — 아니면 `target3_passed`, 산출하지 못하면 `target3` 로 제외

**돌파 이후 플랜(목표가 측정 이동 50%·100%)은 목록에서 뺀다.** 목표가 박스 상단 위에 있어 "1차 목표 = 박스 중간" 이라는 열 제목이 거짓이 되기 때문이다. 제외 건수와 사유는 상단 "🧭 박스 플랜 완성 N/M"의 툴팁과 API `plan_stats.excluded` 에 나온다.

### 8.4 숨은 동작과 되돌리기

- 리더 반전·모멘텀 지속·VCP 신호 **계산과 진입 준비 승격은 그대로**다(점수 미반영, API 응답에도 그대로). 삭제한 것은 화면의 열과 배지뿐이다. 승격으로 진입 트리거가 바뀐 행은 "진입 트리거 출처: 리더 반전 돌파 (스캔 기본 트리거 …)" 가 종목 칸 툴팁에만 남는다(§8.7 에서 진입 트리거 열을 지우면서 셀 툴팁을 옮겼다). 모멘텀·VCP 는 `STOCKORACLE_MOMENTUM_SCAN=0` / `STOCKORACLE_VCP_SCAN=0` 으로 끌 수 있다.
- 응답 캐시 키를 `scan|v7|` 로 올렸다(응답 모양이 바뀌었으므로 이전 캐시를 재사용하지 않음). §8.7 에서 선정 규칙이 바뀌어 `scan|v8|` 로 다시 올렸다.

### 8.5 한계

- **플랜이 완성된다는 것은 가격이 계산된다는 뜻이지 사도 된다는 뜻이 아니다.** 완성 종목 대부분이 "매수 제외·관망 + 조건부 재진입 후보"(박스 이탈 뒤 새 박스 대기)다. 이 후보 가격은 표본이 없는 구조적 가격이다(§7.4).
- (정정: §8.7) 처음에는 목표가 현재가보다 **아래**로 나오는 행을 "목표는 재진입 후보 가격 기준이라 정상"이라며 그대로 보여주고 현재가 대비 %를 빨간색(−)으로 그렸다. 현재가 옆에 놓인 "목표"가 이미 지나간 가격이면 표가 거짓을 말하므로 §8.7 에서 이런 종목은 목록에서 뺐다.
- 시장 국면이 약세/고변동성인 날은 `passes_tech_filters` 가 거의 모두 거짓이라(KRX 46종목 중 0) 15개 모두 3등급 보강으로 채워진다. 이는 이번 변경과 무관한 기존 동작이다.

### 8.6 표 열 순서와 예상 기간·도달 확률 형식 (2026-11-07 2차 요청)

표시만 바꿨다 — 스캔 절차, 종목 선정(플랜 완성 게이트·순위), 가격·손절·재진입·대기 계산은 그대로다.

**열 순서** (`#` 순번 칸 + 11열 = 12칸. §8.7 에서 진입 트리거를 지워 지금은 `#` + 10열 = 11칸): 종목 · 카테고리 · 현재가 · 진입 트리거 · 돌파 신뢰도 · 1차 목표(박스 중간) · 2차 목표(박스 상단) · 손절 기준 · 재진입 후보 · 예상 기간 · 도달 확률. 머리글(`#page-scan thead`)과 `renderScanResult` 의 행이 같은 순서이고, 빈 목록 메시지 `colspan` 은 §8.7 이후 11이다. 이 표에는 정렬·필터·검색 기능이 없다.

**예상 기간** ("예상 대기 시간"의 새 이름, 거래일 기준 · 일 단위):
- `min~max일` = 플랜 `timing.touch.days_if_reached`(닿는 경우의 첫 도달일 25~75백분위, `touch_time_window`)를 그대로 쓴다. 최소=최대면 `N일`.
- 이 창이 없을 때만 엔진이 이미 계산한 최소 대기를 쓴다: `최소 N일`(박스 확정·종가 확인에 필요한 완료 봉 수) / `다음 봉 마감` / `대기 없음`. 범위를 만들어 넣지 않는다. 아무것도 없으면 `산출 불가`.
- 예전 셀의 첫 줄이던 "최소 N거래일(박스 확정)"은 창이 있는 행에서는 툴팁(`wait.detail`)으로 옮겼다.

**도달 확률** (별도 열): `low~high%`, 소수 첫째 자리, `%` 는 끝에 한 번. `low`/`high` 는 `touch_probability_range` 의 변동성 오차 범위(25·75백분위 배율)이고 **새 계산이 아니다**. 예측 탭이 쓰는 정수 반올림 값(`p_horizon`)은 그대로 두고 `box_plan._timing_touch` 에 같은 확률의 소수 첫째 자리 값(`p_horizon_exact`, `p5_exact`)만 추가했다. 범위가 한 점으로 모이면(예: 거의 확실) `100.0%` 처럼 한 값, 확률이 없으면 `산출 불가`.

**확률이 뜻하는 것(변경 없음)**: 20거래일 안에 **도달 기준가**에 한 번이라도 닿을 가능성이다. 기준가는 상태마다 다르다 — 이탈 뒤에는 "이탈 실패 확인가", 박스 안 지지 후보는 "재진입 후보 구간 상단", 박스 안 상단 대기는 "돌파 확인 가격". 1차 목표 도달 확률이 **아니다**. 셀 툴팁에 기준가 이름과 가격이 나온다(`wait.probability.level_label`, `level`). 현재가가 이미 기준가 이상이면 엔진이 터치 모델을 계산하지 않아 확률은 `산출 불가`다(KRX 실측 15개 중 3개).

**가격 칸 보조 문구 제거**: 1차 목표·2차 목표·손절 기준·재진입 후보의 "현재가 ±x.x%" 줄을 그리지 않는다. 가격 색(목표 초록·손절 빨강·재진입 파랑)과 "후보 진입 기준"·"이전 박스 중간"·"조건부" 같은 설명 줄은 유지. `pct_from_quote` 는 API 응답에 그대로 있다.

검증(2026-11-07 KRX 실측 15종목): 모든 행이 12칸, 가격 4칸에 `%`·"현재가" 문구 0건, 예상 기간 = 엔진 `days_if_reached` 일치, 소수 확률의 반올림 = 기존 정수 확률 일치(15/15).

### 8.7 진입 트리거 열 삭제와 "목표는 현재가보다 높아야 한다" (2026-11-07 3차 요청)

**1) 열 삭제.** 표에서 진입 트리거 열을 지웠다(머리글·행·빈 목록 `colspan` 11). `entry_trigger` 는 API 응답에 그대로 있다. 리더 반전·모멘텀·VCP 승격 행의 "진입 트리거 출처" 툴팁은 종목 칸으로 옮겼다(승격 출처가 화면에서 사라지지 않게).

**2) 왜 목표가 현재가보다 낮게 나왔나 — 원인.** 계산 오류가 아니라 **기준점이 다른 두 가격을 한 표에 나란히 놓은 것**이다.

- `box_plan._targets` 는 목표를 **재진입(풀백) 매수 기준가보다 높은 것**만 남긴다(`p <= entry_ref` 면 버림). 현재가와는 비교하지 않는다. 박스 중간·상단은 박스 구조 가격이라, 현재가가 이미 그 위로 올라가 있어도 "손절·재진입 하단 기준의 1·2차 목표"로는 맞는 값이다.
- 그런데 스캔 표는 현재가 바로 옆에 놓으므로, 현재가보다 낮은 "1차 목표"는 이미 지나간 가격을 목표라고 부르는 셈이다.
- 세 경로로 생긴다(2026-11-07 실데이터, 목표 외 4항목이 모두 산출된 플랜 기준: KRX 28개 중 13개, US 74개 중 37개가 1차 목표 ≤ 현재가):
  1. `new_base`(박스 하단 이탈 뒤 새 범위 형성 중, 가장 많음): 하락 구간의 형성 범위는 [최저점, 그 뒤 최고점](`box_sequence.scan_boxes`)이다. 저점에서 절반 넘게 반등한 종목은 범위 중간 **위**에 있다.
  2. `reclaim`(이탈한 옛 박스, 가격이 박스 안으로 복귀): 옛 박스의 중간·상단을 가격이 이미 넘었다. 옛 상단 위까지 올라간 종목은 2차 목표도 현재가 아래였다(KRX 035420: 현재가 190,200 / 2차 목표 185,000).
  3. `range_support`·`new_box_above`(돌파 실패 뒤 박스 안 복귀, 위쪽 새 박스): 같은 효과.

**3) 수정.** `scan_box_plan.summarize_plan` 의 "완성" 조건에 **1차·2차 목표가 표의 현재가보다 엄격히 높을 것**을 더했다. 아니면 제외하고 사유를 `plan_stats.excluded` 에 센다.

| 제외 키 | 뜻 |
|---|---|
| `target_mid_passed` | 1차 목표(박스 중간) ≤ 현재가 |
| `target_top_passed` | 2차 목표(박스 상단) ≤ 현재가(이때는 1차도 ≤ 현재가이므로 상단 하나만 보고) |
| `quote` | 현재가를 몰라 비교 불가 |

가격이 목표와 정확히 같으면(호가 단위로 내림한 값) "높지 않음"으로 본다. 가격·확률·손절·재진입 **계산은 그대로**이고 순위(종합점수·등급·MMR)도 그대로다. 바뀐 것은 목록에 오를 종목뿐이다. 응답 캐시 키 `scan|v8|`, 플랜 요약 버전 `2026-11-07.scan-box-plan-v2`.

실데이터(2026-11-07, 로컬 재실행):

| 시장 | 평가 | 플랜 완성(이전 → 이후) | 제외 사유(이후) | 표시 |
|---|---|---|---|---|
| KRX | 44 | 28 → 17 | 돌파 이후 측정 이동 13 · 1차 목표 ≤ 현재가 13 · 2차 목표 ≤ 현재가 1 | 15 |
| US(≤$23) | 94 | 74 → 38 | 측정 이동 18 · 1차 ≤ 현재가 30 · 2차 ≤ 현재가 7 · 데이터 부족 1 | 15 |

완성 종목 전부에서 `현재가 < 1차 목표 < 2차 목표`가 성립함을 확인했다(위반 0건). 표시는 여전히 15개까지 채워진다.

**한계**
- **예측 탭의 박스 실행 플랜은 바꾸지 않았다.** 거기서는 재진입 구간을 먼저 보여주고 목표를 그 매수가 기준으로 읽도록 되어 있어 현재가보다 낮은 목표가 나올 수 있다. 스캔 표에서만 "현재가 위 목표"를 목록 조건으로 둔다.
- **현재가에 아주 가까운 1차 목표는 걸러지지 않는다.** 엄격한 부등호만 쓰므로 1차 목표가 현재가의 +0.1% 위인 종목도 남는다(KRX 실측 17개 중 6개가 +1% 이내, 최소 +0.11%). 최소 거리를 두려면 근거가 되는 기준(예: ATR 배수)을 따로 정해야 해서 임의로 넣지 않았다.
- 남은 종목 대부분은 여전히 "매수 제외·관망 + 조건부 재진입 후보"다(§8.5). 목표가 현재가 위라는 것은 가격 배치일 뿐 도달 가능성이나 매수 적합성이 아니다.

### 8.8 머리글 이름 정리와 3차 목표 (2026-11-07 4차 요청)

**머리글.** "1차 목표(박스 중간)" → **1차 목표**, "2차 목표(박스 상단)" → **2차 목표**. 의미(박스 중간·상단)는 머리글 툴팁에 남겼다. 3차 목표 열을 2차 목표 바로 오른쪽에 더했다. 열 순서는 `#` · 종목 · 카테고리 · 현재가 · 돌파 신뢰도 · 1차 목표 · 2차 목표 · **3차 목표** · 손절 기준 · 재진입 후보 · 예상 기간 · 도달 확률(12칸, 빈 목록 `colspan` 12).

**3차 목표의 값.** 예측 탭 🛡️ 리스크 관리와 목표 청산 › ⚖️ 중립적 카드의 **TP2 "목표 가격 범위" 중 가장 높은 가격**(`price_range` 의 큰 값)이다. TP2 행은 `[저, 고]` 범위로 표시되므로 고가 쪽을 쓴다. TP1·TP3 이 아니다.
- 계산: 예측 탭과 같은 `add_indicators` → `calc_risk(...)["balanced"]["tp_levels"][1]` 을 스캔 스냅샷(일봉 OHLCV)으로 돌린다(`api/index.py::_scan_attach_target3`, 요약은 `scan_box_plan.summarize_target3`). 응답 `box_plan.target3` 에 `price/low/high/return_pct/prob_pct/days/not_above_target2` 가 들어간다.
- **순위에는 쓰지 않는다**(종합점수·등급·MMR). 처음에는 표시 전용이라 선정이 끝난 15종목만 계산했으나 §8.9 에서 목록 조건이 되어 계산 대상·시점이 바뀌었다.
- 이 단계의 캐시 키는 `scan|v9|`, 플랜 요약 버전 `2026-11-07.scan-box-plan-v3` 였다(현재는 §8.9 의 `scan|v10|` · `v4`).
- 색칠(파란 그라데이션 행 강조)은 미국 종목의 중립적 TP2 에만 있다(`highlight_primary_exit`, 미국 한정). 3차 목표는 시장과 관계없이 TP2 값을 쓴다.

**예측 탭 값과 완전히 같지는 않다.** 같은 함수·같은 로직이지만 입력이 다르다.
- 현재가: 스캔은 스캔 표의 현재가(일봉 종가)를, 예측 탭은 실시간 시세를 쓴다(오늘 비교: 000660 1,132,000 vs 1,176,000).
- 이벤트 위험: 예측 탭은 뉴스·공시·실적 일정을 반영하고(손절 확대·목표 축소), 스캔은 수집하지 않는다.
- 차트 패턴 병합: 예측 탭만 한다(오늘 비교한 4종목은 병합 0건이었다).
- 지표 워밍업: 스캔은 1년 일봉만 쓴다.
- 오늘 4종목(UMC·RGTI·000660·058470) 비교에서 TP2 고가(= 3차 목표)가 0.6~2.6% 어긋났다(예측 탭이 UMC·000660·058470 은 더 높고 RGTI 는 더 낮았다). 같은 종목도 예측 탭 값이 조회할 때마다 현재가에 따라 움직인다.

**한계 — 3차 목표가 2차 목표보다 낮은 종목이 있다.** 1·2차는 박스 구조 가격, 3차는 ATR·피보나치 모델 가격이라 서로 다른 모델이다. 2026-11-07 실데이터에서 표시 종목 중 KRX 3/15, US 5/15 에서 3차 ≤ 2차였다(전체 완성 플랜 기준으로는 53개 중 22개). 이 단계에서는 "2차 목표 이하"를 표시하기만 했고, 사용자가 "그런 종목 제외"를 택해 §8.9 에서 목록에서 뺀다.

### 8.9 3차 목표가 2차 목표 이하인 종목 제외 (2026-11-07 5차 요청)

**규칙.** 목록에 오르려면 `현재가 < 1차 < 2차 < 3차` 가 성립해야 한다. 3차 목표(중립적 TP2 고가)가 2차 목표(박스 상단) 이하이거나 계산하지 못한 종목은 뺀다. 3차 목표 값·순위·다른 숫자는 바꾸지 않고 목록에서 거르기만 한다. 사유는 `plan_stats.excluded` 에 `target3_passed`(2차 이하) · `target3`(산출 불가)로 센다.

**구조 변경 — 3차 목표를 선정 전에 계산한다.** 거르려면 표시 15종목이 아니라 **플랜이 완성된 후보 전체**를 알아야 한다(제외된 자리를 다음 순위가 채우므로).
- `attach_box_plans` → 플랜 완성 후보를 종합점수 순으로 `_scan_attach_target3` 에 넣어 `box_plan.target3` 계산 → `scan_box_plan.apply_target3_gate` 가 제외 처리 + `plan_stats`(완성·미완성·사유별 건수) 동기화 → 등급·MMR 선정(기존과 동일).
- 비용: 후보 전체 계산. 지표를 `calc_risk` 가 읽는 열(ATR·BB·MA·RSI·MACD·ADX/DI)까지만 계산하도록 `add_indicators(..., core_only=True)` 를 더했다. 공통 열은 같은 식이라 `calc_risk` 결과가 전체 지표 때 결과와 같다(합성 12종목 12/12 일치). 종목당 약 208ms → 약 119ms, 완성 후보 약 15~38개면 2~5초. 스레드 병렬은 GIL 때문에 이득이 없었다(36종목 직렬 7.6초 vs 4스레드 8.8초).
- **시간 보호는 Vercel 에서만**(`os.getenv("VERCEL")`): 수집 시작 후 `SCAN_TARGET3_BUDGET_S`(52초)를 넘기면 남은 종목은 계산하지 않고 `target3_unchecked` 로 표시한다. 이런 종목은 "2차 이하로 확인된 것"이 아니라 "확인 못 한 것"이라 **제외하지 않고** 남기며(느린 실행이 빈 목록이 되지 않게) 3차 목표 칸은 `산출 불가`, 상단 "🧭 박스 플랜 완성" 툴팁과 `plan_stats.target3_unchecked` 에 건수가 나온다. 로컬 개발 서버는 이 제한이 없다(처음에 모든 환경에 걸었더니 이 PC 의 느린 US 스캔이 52초를 넘겨 전 종목이 미확인으로 남았다).
- 응답 캐시 키 `scan|v10|`, 플랜 요약 버전 `2026-11-07.scan-box-plan-v4`.

**화면.** "2차 목표 이하" 보조 표시는 지웠다(서버가 그런 종목을 내보내지 않는다). 3차 목표 머리글 툴팁, 소개 문구, 빈 목록 메시지, `filter_desc` 에 "현재가 < 1차 < 2차 < 3차 목표"를 적었다.

실데이터(2026-11-07, 로컬 실제 `/api/scan` 경로):

| 시장 | 평가 | 플랜 완성(3차 게이트 전 → 후) | 3차 게이트 제외 | 표시 |
|---|---|---|---|---|
| KRX | 40~43 | 15~16 → 10~11 | 5 (`target3_passed`) | 10~11 |
| US(≤$23) | 94 | 37 → 21 | 16 (`target3_passed`) | 15 |

표시된 모든 행에서 `현재가 < 1차 < 2차 < 3차` 가 성립함을 확인했다(위반 0건). 같은 날 실행마다 현재가가 움직여 건수가 약간 다르다.

**한계**
- **KRX 는 목록이 15개를 못 채운다**(10~11개). 완성 후보가 적은 날 이 조건이 더해지면 그만큼만 보여준다(미완성으로 채우지 않음, §8.2).
- 3차 목표는 예측 탭 값과 입력이 달라 0.6~2.6% 어긋날 수 있다(§8.8). 그래서 "예측 탭에서는 3차 > 2차"인 종목이 여기서 제외되거나 그 반대일 수 있다.
- 3차 > 2차 가 "엄격한 부등호"뿐이라 2차 목표 바로 위(예: US GAP 2차 $22.51 / 3차 $22.61)인 종목도 남는다. 최소 거리 기준은 근거가 없어 두지 않았다.
