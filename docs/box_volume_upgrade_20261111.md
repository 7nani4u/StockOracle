## ② 문제 재정의

평가 대상은 “가격·확인 봉으로 매수라고 판단했던 사례 중 실제 목표 도달 전에 손절되는 사례가 줄어드는가”다. **20거래일 안 손절 전 1차 목표 도달률**, 비용 반영 수익률·평균 R·거래 수를 함께 비교한다. 박스 상·하단 가격을 임의로 좁혀 목표 도달률만 높이는 방식은 사용하지 않는다. 원래 도달확률·대기기간 산식도 검증 없이 거래량 가중치로 바꾸지 않는다.

### 세 가지 프레임워크와 반증

**PR — 문제 재정의.** 첫 번째로 적용했다. 사용자의 “거래량을 포함한 박스 플랜 정확도”라는 목표를 원래 카드와 스캔 표의 판정 개선으로 한정했다. 이전 작업의 계좌 자본·수량·보유 시각·추가 화면은 이 목표를 넓혀 해석한 결과였으므로 먼저 되돌렸다. 이번에는 가격이 닿을 위치와 매수 판단을 구분한다. 거래량은 박스가 돌파되었다는 가격 사실을 지우는 값이 아니라, 그 돌파 뒤의 재확인을 매수로 승인할 근거가 충분한지를 평가하는 입력이다. 가정은 완료 일봉 기반의 기존 롱 전용 박스 전략을 계속 쓴다는 것이다. 일봉으로 장중 어느 초에 주문이 체결되는지를 추정하는 문제는 범위에 넣지 않았다. 이 재정의 덕분에 화면과 가격 구조를 유지하면서도 실제 판정에 영향을 주는 계산 지점을 정할 수 있었다.

**MDA — 다차원 분석.** 두 번째로 시간·가격·거래량·시장·출처를 함께 추적했다. 시간 차원에서 가장 중요한 문제는 돌파일과 재확인일이 다르다는 점이다. 돌파 때 거래량이 많았어도 며칠 뒤 눌림목에서는 거래량이 줄 수 있다. 현재 거래량만 돌파 기준에 넣으면 조용한 재확인을 거짓 실패로 볼 수 있다. 반대로 최초 돌파의 거래량이 부족했는데 현재 봉에서만 거래량이 늘었다고 과거 돌파를 확인된 사건으로 바꾸면 시점이 뒤섞인다. 따라서 돌파 직전 20봉 평균을 분모로 고정하고 돌파일부터 최대 두 개의 완료 확인 봉 평균을 비교한다. 가격 차원에서는 원래 박스의 상·하단과 진입·손절·목표의 숫자를 유지한다. 시장 차원에서는 원 단위와 달러 단위에 영향을 받지 않는 상대 거래량을 사용하며, 한국·미국·미국 $23 이하 후보를 나눠 확인한다. 출처 차원에서는 거래량이 0이거나 평균을 만들 수 없는 경우를 확인 성공으로 바꾸지 않는다. 35% 이상 가격 급변 뒤 박스를 다시 시작하는 기존 정책에 맞춰, 새 구간 이전의 거래량을 섞어 비교하지 않도록 했다.

**IA — 반증 우선 검증.** 세 번째로 적용했다. “거래량이 많을수록 항상 좋다”는 가정을 실제 데이터로 시험했다. 돌파 확인만 추가하는 방식, 하단 지지에도 거래량·종가 위치를 요구하는 방식, 조용한 눌림목을 별도 승인하는 방식을 비교했다. 하단 지지까지 강한 조건을 넣은 방식은 개발 기간에서 좋아 보였지만 이후 기간의 평균 R이 악화됐다. 이를 기본 규칙으로 채택하지 않았다. 도달확률에 가격·거래량 변수를 넣는 작은 보정 모델도 개발 기간의 순차 검증 오차가 원래 모델보다 컸다. 따라서 새 확률 모델과 학습된 가중치를 배포하지 않았다. 남긴 규칙은 돌파 사건의 거래량을 확인하는 최소 규칙이며, 거래량이 강하다는 이유로 가격 이탈·손절·실패 상태를 덮어쓰지 않는다. 가정은 직전 20봉 평균 대비 1배를 확인 기준으로 사용한다는 것이다. 이 기준은 미래 수익을 보장하는 최적 상수가 아니며, 여러 후보를 살펴본 탐색 편향도 한계로 기록한다.

**CS — 원래 구조를 유지한 해결.** 적용 순서는 원복 확인, 원인 확인, 순수 거래량 계산, 원래 결정 계층 연결, 동일 자료 전후 비교였다. 모든 분기에서 가격을 다시 만들지 않고 `build_execution_plan`이 기존 플랜을 만든 뒤 거래량 확인을 적용한다. 따라서 재확인 매수뿐 아니라 기존에 취소된 계획을 다시 승인하는 우회도 방지할 수 있다. `조건부`로 바뀌어도 진입 후보·손절·목표 숫자는 남긴다. 확인 날짜는 예측하지 않으며 최소 다음 완료 봉부터 새로운 근거를 확인하도록 한다. 이 방식의 제약은 거래량 확인으로 승인 거래 수가 줄어든다는 것이다. 도달률만 높아졌다고 설명하지 않고 거래 수와 수익·위험 지표를 함께 제시한다.

## ④ 개선 아이디어와 적용 결과 — 10개

1. **원래 플랜으로 돌아갈 기준선을 보존한다 — 적용.** 이전 작업에서 어느 파일을 바꿨는지 성공한 패치 기록으로 추출해 그 변경만 역적용했다. 역적용 결과에 같은 패치를 순방향으로 다시 적용했을 때 현재 파일과 정확히 같아지는지 먼저 검사했다. 기존 미커밋 파일을 통째로 초기화하지 않았으며 원래 스캔 가격 상한과 박스 플랜 작업을 보존했다. 원복 후 테스트 907개를 다시 실행해 기준선을 확인했고 API·UI 등 이전에 손댔던 7개 파일의 원복 해시도 마지막에 재확인했다. 개선 결과를 비교할 대상 자체가 바뀌는 문제를 방지하는 절차다.

2. **거래량의 비교 시점을 돌파 사건에 고정한다 — 적용.** 현재 거래량 비율 하나만 보면 돌파 시점의 참여가 충분했는지 알 수 없다. 새 근거는 박스의 실제 `exit_index`를 기준으로 직전 20거래일 평균을 분모로 삼는다. 분모에 돌파 봉을 포함해 큰 거래량이 자기 기준을 끌어올리는 오류를 피했다. 최초 돌파의 비율과 최대 두 개 완료 확인 봉 평균 비율을 따로 저장한다. 이후 봉이 추가돼도 이미 완료된 두 확인 봉의 평균과 그 분모는 바뀌지 않는다. 이로써 과거 돌파와 현재 재확인이라는 서로 다른 사건을 구분하면서 현재 근거의 출처를 추적할 수 있다.

3. **진행 중 거래량을 확정 신호에 넣지 않는다 — 적용.** 기존 예측 탭과 스캔은 진행 중 마지막 일봉을 제외한 자료로 박스 플랜을 만든다. 새 거래량 계산도 이 완료 일봉 입력을 그대로 사용한다. 장중 누적 거래량을 하루 전체 거래량처럼 부풀리거나 시간 비율로 임의 환산하지 않는다. 돌파가 오늘 발생했더라도 아직 하루 봉이 끝나지 않았다면 확인된 거래량으로 취급하지 않는 구조다. 기존 입력 경로를 유지하면서 신호 시점과 거래량 확정 시점이 같도록 했다. 예측·스캔 요약에는 같은 근거를 전달하므로 화면마다 다른 거래량 상태를 사용하는 문제도 줄인다.

4. **조용한 재확인을 실패로 오인하지 않는다 — 적용.** 거래량이 큰 돌파 뒤 눌림목의 거래량이 줄어드는 것은 원래 돌파 거래량이 부족했다는 뜻이 아니다. 단순히 최신 거래량이 평균 미만이면 탈락시키는 방식 대신 최초 확인 봉의 거래량을 사용한다. 새 데이터에는 최근 눌림 거래량과 돌파 확인 거래량의 비율도 참고값으로 남겼다. 이 참고값만으로 매수 상태를 올리는 추가 규칙은 사용하지 않는다. 테스트에서는 돌파가 평균의 여러 배였고 현재 거래량이 작더라도 원래 재확인 매수가 유지되는지 확인했다. 반대로 최근 거래량만 커져도 과거 약한 돌파를 확인된 것으로 바꾸지 않는지 검증했다.

5. **거래량을 확인할 수 없는 경우를 구분한다 — 적용.** 거래량 0, 유효한 이전 평균 없음, 충분한 완료 봉 부족을 확인 성공으로 바꾸지 않는다. 기존 가격 급변 후 새 박스를 계산하는 경우에는 급변 이전의 거래량을 새 구간의 평균에 섞지 않는다. 최신 봉의 비교 평균은 있어도 돌파 사건 직전 20봉이 새 구간 안에 없으면 그 돌파의 거래량은 미확인이다. 실제 서비스와 감사가 이 경우를 동일하게 처리하도록 공통 승인 함수를 사용했다. 결측으로 인한 보류와 관측된 약한 거래량을 구분하므로 근거 없는 중립값 1배를 만들어 매수 판정을 유지하는 오류를 피할 수 있다.

6. **가격 구조를 유지하고 승인 조건을 보강한다 — 적용.** 거래량이 약하다는 이유로 지지·저항 가격을 임의로 움직이지 않는다. 원래 상·하단, 중간선, 진입 범위, 손절, 1·2·3차 목표 산식을 유지한다. 검증한 매수 승인 조건에서 거래량이 부족하면 기존 `매수`를 `조건부 매수`로 낮추며 같은 가격을 남긴다. 이미 `관망·매수 제외·산출 불가`인 계획은 거래량이 크더라도 올리지 않는다. 71종목의 마지막 시점에서 원래 엔진과 박스 경계·모든 가격 숫자를 직접 대조해 불변임을 확인했다. 신호 품질의 개선과 목표를 낮춰 도달률만 높이는 변경을 혼동하지 않기 위한 기준이다.

7. **기존 카드의 확인 조건·근거에 연결한다 — 적용.** 별도의 보유 종목 페이지나 표 열을 추가하지 않았다. 거래량 상태는 원래 박스 플랜의 확인 조건과 계산 근거에 들어가고 스캔 요약에도 보존된다. 보류된 계획의 행동 문장은 더 이상 “지금 살 수 있다”고 말하지 않으며 거래량을 동반한 새 확인 근거를 기다린다고 설명한다. 기존 신호 확인 조건도 이에 맞춰 미충족으로 표시한다. 다만 조건이 언제 충족될지는 예측하지 않으며, 최소 다음 완료 봉부터 다시 검토한다는 뜻으로 대기 기준을 제공한다. 원래 화면과 수치 계약을 보존하면서 판정·문장·조건 사이의 모순을 방지한다.

8. **하단 지지에는 일률적인 거래량 문턱을 강제하지 않는다 — 검증 후 제외.** 돌파와 지지는 가격 사건의 성격이 다르다. 거래량이 작아 매도 압력이 줄어드는 경우에도 하단 지지가 성립할 수 있어 높은 거래량을 모든 경우에 요구하면 좋은 신호도 지울 수 있다. 개발 기간에서 좋아 보인 하단 지지 조건이 이후 기간에서는 평균 R을 악화시켰다. 따라서 기본 플랜은 하단 지지의 원래 가격·확인 봉 조건을 유지한다. 상대 거래량과 거래량 가중 종가 위치는 근거로 제공하지만 독립적인 매수 차단·승격 규칙으로 사용하지 않는다. 단, 거래량 자체가 0이거나 유효하지 않은 경우는 자료 확인 문제로 보류한다.

9. **도달확률에 검증되지 않은 거래량 가중치를 넣지 않는다 — 검증 후 제외.** 원래 터치 모델에 가격 추세·상대 거래량·거래량 가중 종가 위치를 넣는 작은 보정 모델을 시험했다. 개발 기간의 순차 검증 Brier 오차는 원래 0.1800, 가격 보정 0.1813, 거래량 포함 보정 0.1828로 오히려 커졌다. 이 결과를 근거로 학습 가중치와 새 확률 모델은 적용하지 않았다. 기존 예상 기간·도달확률 산식은 그대로다. 거래량을 포함한다는 이유로 표시 확률을 임의로 높이거나 낮추지 않는 것이 중요하며, 실험 실패 결과도 별도 JSON에 남겨 이후 같은 가정을 반복 채택하지 않도록 했다.

10. **전후 비교와 추가 종목 검증을 재현 가능하게 만든다 — 적용.** 새 감사 스크립트는 기존 플랜·같은 체결 규칙·같은 비용에서 거래량 승인 조건만 바꿔 비교한다. 시간 경계에 걸친 미래 20봉을 개발 자료에서 제거하고 종목당 한 포지션을 유지한다. 기존 표본 외에 규칙을 먼저 고정하고 추가 종목군을 수집했으며, 미국 $23 상한을 반영한 별도 결과도 생성했다. 모든 매수 후보에서 서비스와 감사의 승인 판정이 같은지 검사한다. 도달률 외에 거래 수·수익·평균 R과 불리한 결과를 함께 기록하고 원자료 해시를 남긴다. 같은 자료의 여러 비교를 새로운 독립 검증처럼 부풀리지 않는 방식이다.

## ⑤ PDCA

**계획:** 원복 상태를 먼저 입증하고 거래량이 계산만 되고 판정에는 연결되지 않은 지점을 확인했다. 가격 구조와 화면을 유지한 채 거래량 확인의 기여를 분리 평가하기로 했다.

**실행:** `box_volume.py`의 순수 계산을 `box_sequence`와 `box_plan`에 연결했다. `box_prediction`과 `scan_box_plan`에는 같은 근거를 보존했다. 신규 계좌·수량·기간 UI는 추가하지 않았다.

**점검:** 원복 기준선 907개, 최종 전체 **926개·하위 테스트 6개 통과**. 기존 52종목 49,740시점 감사, 추가 종목군 19종목 18,191시점 감사, 미국 가격 상한 검사, 실제 서비스·감사 승인 일치 검사, 71종목 가격 불변 검사를 마쳤다. 원래 API·12열 UI는 원복 해시와 화면 계약 테스트로 확인했다.

**조치:** 최소 돌파 거래량 확인을 기본 연결로 남기고, 검증에서 악화된 하단 지지 강화·확률 보정은 적용하지 않았다. 앞으로도 거래량을 이유로 가격 실패를 덮지 않고, 표본 밖 성과가 악화되면 `volume_policy="off"`로 같은 가격 구조를 재현해 비교할 수 있다.

```powershell
python -m pytest -q --disable-warnings --maxfail=5
python scripts/audit_box_volume.py --stride 1 --out docs/backtests/box_volume_audit_20261111.json
python scripts/audit_box_volume.py --reuse --rows tmp/box_volume_candidates_final.json --scan-price-cap --out docs/backtests/box_volume_scan_cap_20261111.json
python scripts/audit_box_volume.py --cache-dir tmp/box_volume_frozen_cache --policies off,breakout --rows tmp/box_volume_frozen_rows_final.json --out docs/backtests/box_volume_validation_20261111.json
```

추가 종목군 CSV는 이번 검증에서 내려받아 `tmp/box_volume_frozen_cache`에 보관했으며 소스 해시는 검증 JSON에 기록했다. 다른 기기의 검증에는 같은 원자료가 필요하다. 재수집 시 공급자의 수정주가 정정으로 결과가 달라질 수 있다.

## ⑥ 결론

원복 후 원래 박스 플랜에 거래량 확인을 직접 연결했다. 박스 가격을 다시 설계하거나 별도 계좌 시스템을 붙인 변경이 아니다. 기존 표본의 매수 승인 사례에서는 목표 도달률이 개선됐지만 표본 감소·시장별 차이·새 종목군의 평균 R 소폭 악화도 확인됐다. 따라서 **거래량 근거를 갖춘 조건부 판정 개선**으로 설명하며, 미래 가격·매도 날짜의 확정적 정확도 향상으로 주장하지 않는다.
