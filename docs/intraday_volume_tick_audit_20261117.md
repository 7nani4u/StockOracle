## 1. 결론

1. **장중에는 같은 종목·같은 가격이라도 조회 시각만으로 🔮 예측 탭의 숫자가 바뀌고 있었다.** 마지막 일봉을
   '진행 중'으로 둔 채 그 봉의 누적 거래량만 최종값의 30%와 100%로 바꿔 보니 52종목 전부에서 시각 필드를 뺀
   338개 출력 경로가 달라졌다. 돌파 확률 최대 29.8%p(상위 10% 17.9%p), 1차 탐색 구간 1단계 가격 최대 9.7%,
   2차 매수 구간 하단 최대 3.8%, 하락 위험 점수 ±8점(16종목), 횡보 시나리오 +3%p(31종목), TP1 도달 확률
   최대 4.4%p. 2026-10-09 감사가 네 곳(4단계 점수·하이브리드·상관 엔진·박스)만 '직전 확정 봉 기준'으로 고치고
   나머지 소비자는 후속 과제로 남겨 둔 것이 원인이다(§3).
2. **수정 후 장중 화면은 조회 시각과 무관하고, 예전보다 같은 날 마감 후 화면에 가깝다.** 분석 사본의 오늘 거래량을
   직전 확정 봉 거래량으로 둔다. 넣을 값은 다섯 후보를 같은 데이터로 비교해 골랐다(52종목 × 7개 날짜 = 364표본):
   예전 동작 대비 14개 지표 모두에서 마감 후 값에 가까웠고(장 30% 시점 돌파 확률 차이 11.7→6.4%p, 하락 위험 점수
   2.47→1.78, 2차 구간 하단 0.43→0.24%), 30%↔60% 시점 사이의 수치 차이는 0 이다(§3.3).
3. **미국 종목 가격의 절반이 float32 오차를 갖고 있어 내림 반올림에서 한 호가씩 빠졌다.** 야후 일봉은 센트 가격을
   float32 로 저장한 값(17.07 → 17.06999969482422)이라 52종목 캐시의 미국 OHLC 13만 값 중 51.4%가 기존 허용 오차
   (상대 1e-9)를 넘고, 25.6%는 floor 에서 한 호가가 빠진다. 그 결과 SOFI(2026-09-15) 보수적 TP1 범위가 현재가
   17.07 에서 시작했다. 허용 오차를 float32 정밀도를 덮는 상대 1e-6 으로 바꿨다(§4). 매수 구간 감사의 보정 지표는
   바뀌지 않았다(Brier 0.1993, AUC 0.7703 동일).
4. **코스닥 호가표가 2023-01-25 개편 이전 규칙이었다.** `_krx_tick_size` 가 코스닥 20만원 이상을 100원으로 두어
   국내 개장 급등 카드의 목표·손절가가 주문할 수 없는 가격이 될 수 있었다. 개편 이후 유가증권·코스닥·코넥스는
   같은 표(20만~50만원 500원, 50만원 이상 1,000원)를 쓴다(§5).
5. 방향 확률·점수는 이번 변경으로 바뀌지 않았다. 예측 탭의 방향 예측력(AUC≈0.51)을 높였다고 말할 근거는 없다 —
   개선은 **재현성(조회 시각 불변)·입력 정직성·가격 정밀도**다.

## 2. 방법 — 실제 route 의 오프라인 재생

`route('/api/stock')` 를 그대로 실행하되 네트워크는 전송 계층(requests·feedparser·미국 실시간 시세 수집기)에서 끊고,
가격 이력만 `datasets/audit_cache` 의 52종목(KRX 26·US 26) 일봉을 가짜 `yf.Ticker` 로 공급한다. 따라서
`fetch_stock_data → add_indicators → 점수·확률·매수 구간·리스크·예측 요약·박스 플랜` 전 과정이 운영 코드 그대로 돈다.
수급·뉴스·ML·실적 일정은 실패 경로로 처리된다(비교하는 구성 모두에 똑같이 적용).

| 점검 | 결과 |
|---|---|
| 같은 프로세스에서 두 번 실행 | 시각 필드 3개(`calendar_generated_at` 등) 외 동일 |
| 다른 해시 시드(PYTHONHASHSEED 1 vs 777) 프로세스 | KRX 26종목 완전 동일. 미국 차이는 전부 하네스가 실시간 시세 수집기(`us_price_fetcher`, 별도 HTTP 스택)를 막지 못해 들어온 실제 프리마켓 시세 — 막은 뒤 동일 |
| 예외 | 52종목 × 전 구성 0건 |
| 정적 점검(심볼 테이블 기반) | 미정의 이름 0, 같은 이름 최상위 정의 중복 0 |
| 화면 불변식(호가 정렬·TP 순서·확률 범위·단계 내림차순·예측 범위 순서) | 위반 1건(SOFI TP1 이 현재가에서 시작) → 수정 후 0건 |

## 3. 결함 1 — 장중 진행 중 봉의 누적 거래량

### 3.1 재현

2026-09-15 기준, `_bar_in_progress` 를 참으로 두고 마지막 봉 거래량만 최종값의 30%/100% 로 바꿔 비교했다.
가격·고저·시가는 같다.

| 출력 | 바뀐 종목 | 최대 변화 |
|---|---|---|
| 돌파 확률 `risk_scenarios.breakout_probability_pct` | 23 | 29.8%p (상위 10% 17.9%p) |
| 1차 1단계 가격 | 9 | 9.7% |
| 2차 1단계 가격 / 2차 구간 하단 | 11 / 18 | 3.6% / 3.8% |
| 하락 위험 점수 | 16 | 8점 |
| TP1 도달 확률(공격적) | 44 | 4.4%p |
| 시나리오 횡보 / 상승 비중 | 31 | 3%p / 2%p |
| 예측 기준가·P10~P90 | 31 | 0.11% |
| 최종 방향 확률 `prob_up`·규칙 점수 | 0 / 2 | 0 / 1점 (2026-10-09 에 이미 고침) |

### 3.2 원인

정규장 중 일봉의 마지막 막대 거래량은 그 시각까지의 누적값이라 최종값 이하다. 2026-10-09 감사는 거래량 *비율*을
한 칸 앞 막대로 보는 처리를 네 곳(`analyze_score` 4단계, 하이브리드 NCS, 상관 엔진 입력, 박스 분석)에만 넣었다.
나머지는 `Volume[-1]` 을 그대로 읽는다:

- `calc_risk`: `breakout_probability_pct = 30 + … + (vol_ratio_now − 1)×25`, `heavy_sell_volume`(1.35배+음봉 +10점),
  `low_vol_weak`(0.70배 미만 & MA20 아래 +8점), TP 도달 속도·확률
- `_prediction_feature_profile`: `volume_ratio`·`volume_score` → `prob_adj_pp`, `band_width_mult`
- `calc_buy_price`·가격 구조 군집(거래량 가중)·`calc_pullback_analysis`·`calc_target_price`(5봉 평균)
- `build_prediction_outlook`: `volume_ratio ≤ 0.7` 이면 횡보 +3%p → 시나리오 비중 → 예측 기울기
- `add_indicators` 의 `OBV`·`BUY_PRESSURE` 마지막 값, `_average_recent_turnover`(신뢰도·단타 기간·체결 품질),
  기법 게이트 `context_conditions` 의 거래량 맥락

아침에는 거의 모든 종목이 '거래량 위축'으로 보이고, 돌파 확률이 낮아지며, 마감 무렵 다시 올라간다. 가격이 아니라
시각이 값을 정한다.

### 3.3 수정과 넣을 값의 선택

route 가 분석에 쓰는 사본(`dd`)에서만 오늘 봉의 거래량을 바꾸고, `OBV`·`BUY_PRESSURE` 의 마지막 값을 `add_indicators`
와 같은 식으로 다시 계산한다(`market_briefing/session_bars.settle_in_progress_volume`). 차트 거래량·현재 거래량
표시·박스 분석 입력은 실제 누적값 그대로다. 응답 `data_quality.volume_settle` 에 적용 여부·실제 누적값·대입값·누적
비율이 실리고, 예측 요약의 거래량 상태는 "장중 집계 중 — 판단은 직전 확정 봉 n.nn배 기준, 지금까지 누적 n.nn배"로
표시된다. 끄려면 `STOCKORACLE_INPROGRESS_VOLUME_SETTLE=0`.

### 3.4 남은 시각 의존(고치지 않음)

진행 중 봉의 고가·저가도 장중에 넓어진다. 같은 하네스로 고저 범위만 30%/100% 로 바꾸면 ATR 은 중앙값 1.8%(최대
4.6%), 예측 σ 는 중앙값 0.3%(최대 1.0%) 달라진다. 1차 구간 단계 가격이 최대 10.7% 움직인 종목(RKLB)은 ATR 때문이
아니라 오늘 저가가 새로 찍히면서 기준 군집이 47.3 → 53.2 로 바뀐 것이다. 이는 실제로 체결된 가격이 늘어나는
정보라 거래량 누적(최종값보다 항상 작은 값을 최종값처럼 읽는 편향)과 성격이 다르고, 진행 중 봉의 가격을 지표에
넣는 것은 이전 세션의 의도된 설계다. 바꾸지 않고 수치만 남긴다.

## 4. 결함 2 — float32 가격의 호가 반올림

`_snap_tick_units`(api/index.py)와 `box_plan.round_tick` 은 `price / tick` 이 정수와 상대 1e-9 이내면 그 정수로
맞춘 뒤 floor/ceil 한다. 2026-10-09 에 4.26/0.01 = 425.99999999999994 같은 float64 오차를 막으려고 넣은 값인데,
야후 일봉의 float32 오차(상대 최대 2⁻²⁴ ≈ 6e-8)는 덮지 못한다.

- 52종목 캐시 미국 OHLC 130,424값: 51.4% 가 1e-9 를 넘는 오차, 25.6% 는 floor 에서 한 호가가 빠짐
- SOFI 2026-09-15: 종가 17.06999969482422 → TP1 하한 `floor(현재가 + 1호가)` = floor(17.0799997) = 17.07 = 현재가
- 높은 변동성(ATR 가격의 4~6%) 합성 경로 79개 중 3개에서 같은 현상(테스트로 고정)

허용 오차를 상대 1e-6 으로 올렸다(17달러 종목이면 호가의 0.17%, 20만원 종목이면 0.04% 이내만 같은 호가로 본다).
미국 26종목 매수 구간 감사(`audit_entry_bands.py`, 3,273 시점, 단계 4만여 개)를 예전/새 허용 오차로 각각 돌렸더니
불변식 위반 수(1건, 기존 문서의 ATR 12%+ 예외)·Brier 0.1993·AUC 0.7703 이 같았고, 신뢰도 구간별 표본 수만
±2~4 바뀌었다. 정밀도만 고쳐지고 보정은 그대로다.

## 5. 결함 3 — 코스닥 호가표

`_krx_tick_size` 가 코스닥 20만원 이상을 100원으로 돌려줬다(2023-01-25 이전 규칙). 개편 후에는 유가증권·코스닥·코넥스

호출해 원래 맞는 표를 쓰고 있었고(`box_plan.tick_size` 도 맞음), 영향은 시장 이름이 "KOSDAQ" 로 들어오는 국내 개장
급등 카드였다(예: 401,000원 코스닥 종목의 목표·손절가가 100원 단위). 테스트의 예전 기대값
