## ② 문제 재정의와 전체 구조

기존 문제를 “다섯 가격을 항상 출력하기”에서 “동일한 관측 구조에 근거하여 유효한 조건부 가격만 출력하기”로 재정의한다. 매수 1차와 2차는 가격 깊이보다 진입 목적과 확인 조건으로 구별한다. 매도 3개 전략 역시 반드시 모두 성립하는 것으로 간주하지 않는다.

`dev_server.py`는 표준 라이브러리 HTTPServer로 `api/index.py`의 handler를 실행한다. `api/index.py`에는 데이터 공급원 병합, 현재가 보정, 지표·점수·예측 계산, API 응답과 HTML·CSS·JavaScript가 함께 존재한다. `market_briefing/`에는 패턴, 시장 상태, 신뢰도, ML, 확률 보정, 데이터 정합성 등 기능별 모듈이 있다. `tests/`는 네트워크 없는 합성 사례와 응답·표시 계약을 검증하고, `scripts/`, `tools/`, `docs/`, `datasets/`는 연구·감사·백테스트·데이터 자산을 담는다.

기존 예측 경로는 현재가 보정 이후 `calc_risk`, `calc_buy_price`, 목표가·눌림목 계산, 상관 분석, 확률 보정, `build_prediction_outlook`를 거쳐 응답을 생성한다. 기존 매수는 두 번째 가격군을 첫 번째보다 반드시 낮게 배치하고, 구조가 부족해도 ATR 추정값을 표시하는 경로가 있었다. 이는 반등 확인 후 본 진입과 근거 부족 시 보류라는 요구와 충돌한다. 기존 매도 또한 목표·확률·예상 기간을 반복 생성하므로 새 관측 가격을 단순히 옆에 추가하면 서로 다른 목표가가 병존할 위험이 있다.

새 `market_briefing/box_range.py`는 OHLCV 분석을, `market_briefing/box_prediction.py`는 기존 응답 계약에 결과를 적용하는 작업을 담당한다. API 최종 응답 경로에서 어댑터를 호출하며, `buy_price`, `risk_scenarios`, `pullback_analysis`, `chart_data`에 같은 분석 결과를 연결한다. 기존 예측 탭의 항목명·이모지와 화면 맥락을 유지하면서 박스 전용 표시 경로를 추가한다. 기존 현재가 앵커 계약은 구조 가격을 현재 시세 비율에 맞춰 이동시키지 않으며, 확정 일봉과 실시간 시세의 기준 차이를 명시하는 역할을 유지한다.

## ③ 분석: PR → MDA → CS

### PR: 문제 재정의

선택 이유는 기존 시스템의 출력 강제가 사용자의 실제 목적과 어긋났기 때문이다. 적용 순서는 출력 목적 확인, 가격 근거 분리, 진입 조건 분리, 잘못된 기본값 제거이다. 핵심 통찰은 지지선 접근과 지지선 반등 확인이 서로 다른 사건이라는 점이다. 본 진입 가격이 탐색 가격보다 높아도 더 강한 확인 근거를 가질 수 있다. 반대로 더 싼 가격이라는 이유만으로 안전한 본 진입이 되는 것은 아니다. 매도도 저항 도달 전 청산, 저항 구간 청산, 돌파 이후 다음 저항이라는 사건별로 정의해야 한다.

가정은 입력 OHLCV가 동일 종목·동일 시간 간격·동일 가격 보정 기준이라는 것이다. 이 가정이 깨지면 가격 반복성 자체가 의미를 잃는다. 제약은 영상의 실제 설명이 확인되지 않았고, 차트 구조를 찾는 것과 미래 수익률을 입증하는 것이 다르다는 점이다. 반증 관점에서는 강한 추세에서도 여러 국소 고점·저점이 생길 수 있으므로 “접촉이 많다”만으로 박스로 판정하면 안 된다. 가격 포함률, 폭, 지속 기간, 반응을 함께 요구한다. 위험 재평가는 하단 이탈을 단순 할인 기회로 오해하지 않도록 매수 적합 여부를 별도 비활성화하는 것이다.

### MDA: 시간·가격·인과·계층별 평가

선택 이유는 데이터 시간축과 화면의 현재가가 서로 다를 수 있기 때문이다. 먼저 학습 구간과 최근 확인 구간을 나누고, 다음으로 가격대 폭과 반복 반응을 평가한 뒤, 현재 시세와 실행 가능성을 연결한다. 엔진은 최근 확인 봉을 박스 적합에서 제외하고, 학습 구간 안에서 이웃 봉으로 확인된 고점·저점을 군집화한다. 이후 최신 종가가 상단·하단 허용 범위를 벗어나는지 평가한다. 이는 최근 돌파 봉을 다시 학습에 넣어 저항 자체를 올려 버리는 문제를 줄인다.

가격 차원에서는 고정 원화·달러 오차 대신 관측 True Range로 계산한 ATR 기반 허용 폭을 사용한다. 꼬리 극값은 영역의 기준을, 근처 몸통 중앙값은 거절 경계의 보완 근거를 제공한다. 접촉은 연속 봉을 모두 세지 않고 시간 간격을 두어 집계한다. 계층 차원에서는 원천 데이터 검증, 박스 검출, 상태 분류, 주문 참고 구간, UI 표시를 분리한다. 거래량 비율은 보완 증거로 표시하며, 영상에서 설명된 규칙이나 검증된 예측확률로 표현하지 않는다.

가정은 학습 기간 내 반복 구조가 최근에도 참고할 가치가 있다는 것이다. 제약은 매개변수가 기본 설정일 뿐 모든 시장에서 최적이라고 입증되지 않았다는 점이다. 확인 봉 수·접촉 간격·포함률은 설정 객체로 조정할 수 있으나, 값을 바꾼 후 시장별 검증이 필요하다. 대안은 이동창·다중 기간 박스와 강건 분위수 영역이다. 반증은 접촉 간격을 바꾸었을 때 박스가 사라지거나 가격 보정 이후 구조가 급변하는 경우다. 이런 민감성은 신뢰도 저하 근거이지 임의로 무시할 노이즈가 아니다.

### CS: 복잡성 해결과 계약 정합성

선택 이유는 기존 예측 계산을 전면 교체하면 다른 탭과 연구 도구의 회귀 위험이 커지기 때문이다. 적용 순서는 독립 엔진 작성, 단일 응답 어댑터 연결, 표시에 조건부 가격 지원, 회귀 검증이다. 새로운 결과를 한 번 계산하고 참조하도록 하여 매수와 매도의 지지·저항 불일치를 줄인다. 어댑터는 기존 매수 가족을 목적별 박스 구간으로 갱신하고, 매도 목표를 관측 저항에 맞추며, 눌림목 목표도 같은 결과에 연결한다. 기존 종합 위험이 주의 또는 이탈 대기로 판단한 경우 새 박스 신호가 이를 우회하여 신규 진입을 허용하지 않는다.

핵심 제약은 기존 함수의 확률·비중·단계 수 계약과 새 조건부 구간 계약이 다르다는 것이다. 따라서 관측 구조 점수를 승률처럼 표시하거나 기존 3밴드·5단계 감사 통과를 새 경로의 성공 기준으로 삼을 수 없다. 공격 목표는 확정 돌파와 과거에 관측된 다음 고점이 모두 있을 때만 산출하고, 근거가 없으면 보류한다. 이 기준도 미래 상승을 보장하지 않는다. 과거 데이터의 특정 시점 분석은 해당 시점까지의 접두 구간만 입력해야 하며, 전체 데이터에서 미리 구한 고점을 과거 신호에 재사용하면 미래 참조가 된다. 기존 단순 가격 접촉 학습 모형은 반등 확인 진입을 정확히 재현하지 못하므로 별도 검증 없이 새로운 승률로 재사용하지 않아야 한다.

## 실제 추가 계산과 제한

`BoxRangeConfig`는 학습 길이, 최소 봉 수, 확인 봉 수, 독립 접촉 간격, 최소 지속 기간, ATR 허용 폭, 최소 박스 폭과 가격 포함률 등을 설정한다. 이 값은 절대적인 자연법칙이나 영상에서 확인된 기준이 아니다. 엔진은 배열 길이·유한 숫자·양수 가격·OHLC 순서·음수 거래량을 검증한다. 부정합이나 봉 부족이면 `insufficient_data`, 반복 구조가 없으면 `no_box`를 반환한다.

상태는 박스 유지, 지지 반등, 저항 재하락, 돌파 대기·확정, 이탈 대기·확정, 상단 돌파 후 재진입으로 나뉜다. 탐색은 지지 영역과 현재 위치를, 본 진입은 지지 접촉 이후 상승 종가와 지지 상단 회복을 사용한다. 보수적 매도는 저항 전 ATR 여유를 둔 구간, 중립은 저항 영역, 공격은 확정 돌파 이후 과거 다음 고점 영역이다. 어댑터는 현재 시세가 진입 영역에서 멀어졌으면 재시험 대기로 낮추고 진행 중 마지막 봉을 확인 데이터에서 제외한다. 구조 신뢰도는 규칙 점수이며 경험적으로 보정된 성공 확률이 아니다.

## ④ 분석 기반 개선 아이디어 10개

아래는 현재 변경의 효과를 확대하기 위한 후속 제안이다. 구현 완료 항목으로 읽으면 안 된다.

1. **영상 규칙의 검증 가능한 명세화.** 캡처나 자막을 확보하면 각 장면의 설명을 관측 조건, 가격 설정, 무효화 조건으로 분리하여 표로 기록한다. 예를 들어 “같은 저점”이 꼬리의 최소값인지 종가의 중앙 영역인지 장면 근거를 연결하고, 구현 설정과 대응시킨다. 영상에 없는 ATR·거래량·확인 봉 기준은 별도 보완 명세에 둔다. 이 과정은 영상 기반 재현과 개발자가 추가한 가정이 섞이는 문제를 막으며, 사용자가 기준을 바꾸었을 때 어떤 판단이 달라지는지 검토할 수 있게 한다.

2. **확정 봉과 실시간 시세의 명시적 이원 계약.** 분석 원천에는 봉 간격·마지막 확정 시각·진행 중 여부를 포함하고, 실행 참고 가격에는 시세 출처·시각·정규장 여부를 포함한다. 둘을 섞어 종가 돌파를 확정하지 않고, 이미 확인된 구조에 현재 시세가 얼마나 떨어져 있는지만 평가한다. 특히 미국 시간외 시세와 한국 장중 누적 거래량에서 기준 혼동을 줄인다. 데이터가 오래되었으면 가격을 자동 이동시키기보다 지연 상태를 표시하고 실행 적합성을 낮추는 것이 관측 근거를 보존한다.

3. **시장별 매개변수 민감도 검사.** 기본 접촉 횟수나 ATR 허용 폭 하나만 검증하지 말고 주변 설정을 순차적으로 바꾸어 상태와 구간이 얼마나 안정적으로 유지되는지 측정한다. 한국 대형주·소형주, 미국 저변동·고변동 종목을 분리하고 박스 검출률과 오탐률을 함께 보고한다. 특정 설정에서만 성과가 좋아지는 경우는 과최적화 가능성을 제기한다. 검증에는 시간 순서가 유지된 독립 기간을 사용하고, 테스트 결과를 보고 설정을 다시 고르는 반복도 개발 이력에 기록해야 한다.

4. **확인 진입을 재현하는 거래 시뮬레이터.** 탐색은 지지 접근, 본 진입은 반등 확인 후 재시험이라는 서로 다른 사건으로 기록한다. 반등 확인 봉의 고가를 같은 봉의 진입 이후 수익으로 계산하지 않고, 다음 거래 가능 시점부터 평가한다. 봉 내부 순서를 모르면 손절 우선 등 보수적 규칙을 적용한다. 수수료·슬리피지·갭을 포함하여 가격대 접촉률, 실제 체결률, 청산률을 분리한다. 기존 ATR 접촉 모형의 결과를 그대로 본 진입 승률로 붙이지 않는 것이 가장 중요한 검증 개선이다.

5. **가격 영역을 구성한 근거의 추적성 강화.** 지지·저항 각각에 첫 접촉 날짜, 최근 접촉 날짜, 독립 접촉 수, 반응 폭, 사용된 몸통·꼬리 통계를 저장한다. 차트에는 필요한 가격 영역만 간결하게 표시하되 상세 설명에서 근거 날짜를 열 수 있도록 한다. 박스가 재계산되어 가격이 이동했을 때 단순 숫자 변경만 보여주지 않고 새 접촉 추가·오래된 접촉 제외·변동성 변경 중 어느 원인이 작용했는지 설명한다. 이 정보는 계산의 정확성과 사용자 이해를 동시에 개선한다.

6. **다중 박스 후보와 우열의 공개.** 현재 최상위 후보 하나를 고르는 방식을 확장하여 가까운 후보의 점수 차이와 서로 다른 가격 영역을 진단 데이터에 남길 수 있다. 후보가 거의 동률이면 단일 선을 확정적으로 제시하기보다 해석 불확실성을 표시한다. 짧은 최근 박스와 긴 역사적 박스가 충돌하는 경우 분석 기간을 명시하고 우선순위를 검증한다. 이는 과거 큰 범위가 최근 구조를 덮어버리거나 최근 좁은 횡보가 큰 추세를 가리는 문제를 발견하는 데 도움이 된다.

7. **돌파 이후 역할 전환과 재시험 상태.** 확정 상단 돌파 뒤 기존 저항이 지지로 바뀌었다고 즉시 단정하지 않고, 재접촉과 종가 유지가 확인될 때 별도 상태로 기록한다. 다음 저항 목표가 있어도 현재 시세가 이미 이를 넘었으면 오래된 청산 목표를 추천하지 않는다. 하단 이탈 후 재진입도 별도로 분류하여 초기 반등과 구조 회복을 구분한다. 확인 규칙은 영상 자료가 확보되면 먼저 대조하고, 자료에 없으면 후속 보완이라는 점을 유지한다.

8. **데이터 품질과 기업행사 점검.** 주식분할·병합·배당 조정, 거래정지, 공급원 병합으로 생긴 비정상 고저가가 박스를 만드는지 확인한다. 모든 OHLC 열이 같은 보정 방식인지 점검하고, 결측을 종가로 자동 채운 데이터가 접촉 횟수를 부풀리지 않도록 원천 품질 플래그를 전달한다. 거래량 0은 진짜 무거래와 공급원 누락을 구분해야 한다. 값이 숫자라는 사실만으로 관측 품질이 확보되지는 않으므로, 이상 구간에서는 목표 보류와 필요한 데이터 안내를 함께 제공한다.

9. **표시·전송·학습의 공통 상태 계약.** 화면에서는 보류인데 텔레그램 요약이나 학습 기록에는 숫자가 남는 상황을 방지한다. 각 구간에 계산 가능 여부, 실행 적합 여부, 비활성 사유, 가격 기준 날짜를 공통 필드로 두고 모든 소비 경로가 같은 의미를 사용하게 한다. 목표 하나만 존재하는 경우에도 다섯 단계가 있는 것처럼 확장하지 않는다. 가격이 없는 상태를 0원으로 바꾸거나 배열 첫 값을 무조건 접근하는 코드에 회귀 검증을 추가하면 출력 안정성을 높일 수 있다.

10. **성과와 불확실성의 분리 보고.** 접촉 횟수·포함률은 구조의 설명력, 방향 정확도는 예측력, 거래 후 수익은 실행 성과로 따로 집계한다. 규칙 신뢰도 80%라는 숫자를 실제 성공률 80%로 읽게 하지 않으며, 향후 보정 시에도 표본 수·평가 기간·시장별 결과를 함께 제시한다. 박스 미형성 비율과 가격 보류율도 성과 보고에 포함하여 좋은 사례만 선택하는 편향을 줄인다. 유효한 가격을 적게 제시하더라도 근거 없는 공격 목표를 줄이는 것이 이번 작업 목적과 일치한다.

개선 아이디어의 실행 우선순위는 데이터 시점 계약, 확인 진입 시뮬레이터, 공통 상태 계약, 영상 대조 순으로 설정할 수 있다. 이 순서는 수익성 주장보다 현재 출력의 의미와 검증 가능성을 먼저 확보하기 위한 것이다. 각 개선은 결과가 좋아 보이는 사례 몇 개로 완료 판정하지 않고, 적용 전후 동일 데이터와 동일 거래 비용을 사용하여 비교한다. 실패 표본을 제외하는 경우에는 제외 사유와 수를 함께 기록하고, 분할 이전의 수정주가처럼 기술적으로 필요한 제외와 성과가 나쁜 구간을 제외하는 행위를 구분한다. 가격 영역이 바뀌었다면 결과값뿐 아니라 어떤 봉이 근거에 추가되었는지 확인하여 계산 변화가 데이터 변화에 따른 것인지 구현 회귀인지 판단한다.

이 열 가지 제안은 서로 독립적인 장식 기능이 아니라 증거 확보, 계산, 표시, 실행, 사후 평가를 연결하는 작업이다. 특히 영상 자료와 실제 데이터가 충돌하면 영상 규칙을 임의로 유리하게 해석하지 말고 충돌 사례를 명시해야 한다. 원본 설명의 적용 범위를 좁힐 필요가 있는지, 시간 간격이 달라졌는지, 아니면 코드가 설명을 잘못 옮겼는지 검토한 후 수정한다. 사용자가 최적화 목표를 지정하지 않은 상태에서 가격 보류율을 낮추기 위해 기준을 느슨하게 만드는 것은 이번 정확성 우선 요구에 부합하지 않는다.
