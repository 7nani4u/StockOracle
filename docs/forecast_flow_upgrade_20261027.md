# 예측 탭 흐름·실행 조건 정합성 개선 — 2026-10-27

## ① 요약

## ② 문제 재정의·완료 조건

요청을 두 종류의 결과로 정규화했다. 첫째, 빈 요소와 중복·혼재된 설명을 제거하여 판단과 행동의 순서를 쉽게 읽을 수 있어야 한다. 둘째, 현재 시스템이 표시하는 진입 상태가 실제 관측된 확인 조건을 충족해야 한다. 정확도를 높인다는 이유로 검증되지 않은 임계값을 탐색하거나 기존 모델의 출처 승인 필드를 채우지 않는다.

완료 조건은 빈 안내 높이 0px, 시나리오가 주문 후보보다 먼저 등장, 박스 플랜의 독립 렌더링과 초기화, 최종 대기 상태를 따르는 배지, 재시험·가격·압력 조건의 일관성, 휴리스틱 중복표 제거, 관련 회귀 검사와 전체 검사다. Python·NumPy/pandas·HTML/CSS/JavaScript 및 기존 Vercel 구조를 유지했다. 지정된 prompt-optimizer는 원래 자문용이고 직접 구현에는 사용하지 말라는 적용 제외 항목이 있으므로, 명시적인 코드 수정 요청에 따라 요구사항 정리만 참고하고 작업을 실행했다.

## ③ 분석: PR → MDA → IA/CS

PR을 먼저 적용한 이유는 화면 요소를 옮기는 일과 예측의 의미를 바꾸는 일을 구분하기 위해서다. 빈 테두리는 정보 부족 경고를 없애야 하는 문제라기보다, 비어 있는 안내 요소의 표현 상태가 잘못된 문제였다. 이에 모든 안내를 지우는 대신 빈 경우만 숨기고 실제 진입 원칙이나 관찰 원칙은 계속 표시했다. 사용자가 처음 읽을 내용은 현재 판단이며, 그 다음은 판단을 뒷받침하는 근거와 가능한 시나리오다. 가격과 행동 조건이 그보다 먼저 등장하면 관망 중인 종목의 목표가가 매수 권유로 읽힐 수 있다. 따라서 시나리오를 진입 카드 앞으로 옮기고, 박스 실행 조건과 실제 가격 밴드를 별도 영역으로 구분했다. 이 순서가 모든 사용자에게 최적이라는 실험 증거는 없으며, 설명과 행동 사이의 의존관계에 따른 설계 판단이다.

MDA는 세 가지 차원을 함께 확인하는 데 선택했다. 화면에서는 섹션의 순서와 모바일 폭을 살폈고, 데이터에서는 완료 일봉과 현재 시세를 구분했으며, 추론에서는 기술지표와 ML 근거의 독립성을 살폈다. 원시 국면이 돌파 확인이라고 해서 최종 실행 상태도 준비라고 볼 수 없다. 종합 위험 판단과 재시험 부족 때문에 플랜은 대기할 수 있는데 기존 화면은 원시 국면의 tradeable 값을 따라 녹색 배지를 만들었다. 새 화면은 플랜의 최종 status와 tradeable을 사용한다. 실제 박스 플랜의 확인 조건도 함께 표시하여 무엇이 충족되었고 무엇이 부족한지 설명한다. 숫자가 없을 때 자바스크립트의 Number(null)이 0이 되는 문제도 피해서, 비교 자료 부재를 0% 성과처럼 읽지 않도록 했다.

IA는 코드의 문구를 실제 조건으로 반증하는 데 사용했다. 돌파 플랜은 ‘재시험 종가 지지 + 매수 압력’을 조건으로 안내했지만, ready 여부는 현재 시세가 저항 부근인지 여부로만 정해졌다. 최신 완료 봉이 저항을 재접촉하지 않았거나 압력 확인이 없더라도 가까운 시세 하나로 승인될 수 있었다. 기존에 불타기 조건 계산용으로 만들어 두었던 재시험 확인을 최초 진입에도 연결했다. 새로운 지표를 더한 것이 아니라 이미 설명한 조건과 실행 상태를 맞춘 것이다. 양성 대조에서는 재시험과 매수 압력이 확인되고 현재 시세가 허용 범위이면 계속 준비 상태가 된다. 단순히 모든 돌파를 막아 검사를 통과시키는 대안을 배제했다. 일봉은 실제 호가 큐를 제공하지 않으므로 매수 압력은 여전히 OHLCV 근사치라는 제약을 남긴다.

CS는 예측 체인의 상호작용을 정리하는 데 선택했다. 모델이 없을 때의 휴리스틱은 RSI·MACD·ADX 등 기존 기술적 입력을 다시 계산한다. 이를 상관 엔진에서 독립 ML 표로 절반 반영하면 같은 근거를 두 번 세어 신호 일치도를 높일 수 있다. 휴리스틱 결과는 참고 응답으로 남기되 독립 ML 방향표는 기권하도록 바꿨다. 검증된 방향 모델의 정상 표는 계속 유지한다. 또한 전체 기준 검사에서 최근 같은 크기로 덮어쓴 규칙 파일의 갱신이 간헐적으로 누락되는 현상을 발견했다. 파일 식별자·메타데이터를 토큰에 추가하고 갱신 직후 2초 동안 재독하여 새 규칙의 반영을 지연하지 않는다. 수 MB 규칙을 매 신호마다 해싱하는 대안은 스캔 비용 때문에 채택하지 않았고 안정된 파일은 기존 TTL 캐시를 사용한다. 오래된 수정시각과 모든 식별 메타데이터를 보존한 인위적 변경까지 탐지하는 콘텐츠 무결성 검사는 이번 수정의 보장이 아니다.

반증 결과는 유리한 것과 불리한 것을 함께 기록한다. 과거 캐시 52종목·19,700시점에서 돌파 후보는 48건이었다. 기존 가격 근접만으로 ready였을 1건은 MU의 2023-05-23이며 최신 완료 봉의 재시험이 없어 새 규칙에서 대기한다. 이 비교에서 새 ready는 0건이다. 이는 관측한 후보의 조건 일관성이 개선됐다는 증거이지 거래 선택 능력의 개선 증거는 아니다. 선택적 예측의 기권이 늘어났으므로 향후에는 적중률뿐 아니라 커버리지와 비용 후 성과도 동시에 평가해야 한다.

## ④ 개선 아이디어 10개·우선순위

1. **빈 안내는 빈 상태로 렌더링한다 — 적용.** 안내 문구를 비운 뒤 배경과 테두리만 남으면 사용자는 정보가 누락되었거나 로딩이 끝나지 않았다고 생각할 수 있다. CSS의 빈 요소 상태를 사용하면 별도 높이 상수나 화면 크기별 예외 없이 제거할 수 있다. 정상 설명이 있을 때는 기존 안내가 그대로 나타나므로 사용자가 요청한 빈 테두리만 정확히 제거한다. 실제 브라우저에서 내용이 빈 요소의 표시가 none이고 높이가 0px임을 확인했다. 향후 다른 빈 카드에도 같은 기준을 적용하되 데이터 부족 설명 자체를 지우지는 않아야 한다.

2. **판단·근거·시나리오를 행동보다 먼저 제시한다 — 적용.** 현재 상태를 읽은 다음 그 이유와 가능한 전개를 알아야 진입 가격이 어떤 가정 아래의 후보인지 이해할 수 있다. 섹션 순서는 핵심 판단, AI·패턴 보조, 시나리오, 진입 전략, 박스 실행, 청산·위험 관리로 고정했다. 이 구조는 분석을 읽는 사람의 질문 순서와 계산의 의존관계를 연결한다. 사용자 반응을 측정한 사용성 실험 결과는 아니므로, 실제 조회에서 특정 정보가 지나치게 아래로 밀리는지는 후속 피드백으로 조정할 수 있다.

3. **박스 실행을 독립 렌더러로 분리한다 — 적용.** 기존에는 밴드 가격을 만드는 분기 안에서만 박스 플랜을 생성했다. 그 결과 특정 표시 모드에서는 박스가 숨겨지거나 진입 배너와 중복되어 문맥이 흐려질 수 있었다. 별도 순수 렌더러가 박스 응답만 받아 계획을 표시하게 바꾸고, 새 종목에 박스 자료가 없으면 이전 HTML을 지우고 영역을 숨긴다. 이 분리는 사용자에게는 가격과 조건의 구분을 제공하고 개발 측면에서는 화면 상태 초기화의 검사 경계를 명확히 한다.

4. **실행 배지는 최종 플랜을 따른다 — 적용.** 국면 분류는 시장 구조에 대한 해석이고, 실행 상태는 현재 시세와 위험 조건까지 확인한 결과다. 서로 다른 값을 같은 승인으로 표시하면 붉은 경고와 녹색 진입 카드가 공존할 수 있다. 배지와 색상은 최종 ready·tradeable을 기준으로 만들며 대기 상태는 대기로 표시한다. 향후 새 전략을 추가하더라도 국면만으로 준비 배지를 만드는 지름길을 만들지 않아야 한다. 정상 신호를 모두 보류시키는 방식이 아닌지 양성 대조도 함께 유지한다.

5. **재시험 매수는 재시험 관측이 필요하다 — 적용.** 저항 근처의 현재 시세와 완료 봉의 재시험은 별개다. 새 최초 진입 조건은 시세 구간, 최신 완료 봉의 지지 재접촉과 종가 유지, 매수 압력 확인을 모두 요구한다. 이 세 조건을 entry_checks로 반환하여 화면에 충족·미충족을 표시한다. 규칙을 엄격하게 만들면 거래 기회가 줄어들 수 있으므로 그것만으로 예측력이 좋아졌다고 주장하지 않는다. 외부 검증에서는 통과 신호의 결과와 기권한 후보의 결과를 함께 기록해야 한다.

6. **추가 매수는 최초 진입 가능 상태에 종속시킨다 — 적용.** 현재가가 멀리 이탈했거나 없어 최초 진입이 대기인데도, 과거 재시험·압력·거래량만으로 추가 매수가 준비 상태가 될 수 있었다. 추가 매수 준비는 최초 플랜 ready와 기존 거래량 조건을 함께 충족할 때만 가능하게 수정했다. 이는 실제 보유 수량을 추적하는 주문 엔진이 아니라 참고 계획이므로, 현재 보유 여부와 계좌 위험까지 자동 승인한다고 해석하면 안 된다. 실제 불타기 자동화를 하려면 보유 상태와 체결 내역이 추가로 필요하다.

7. **휴리스틱을 독립된 모델 근거로 세지 않는다 — 적용.** 모델 미가용 시 기술지표를 다시 집계한 값은 새로운 관측 자료를 추가하지 않는다. 이를 별도 표로 계산하면 지표가 많아 보이는 착시와 확인편향이 생긴다. 대체 결과는 확인 가능하게 유지하면서 상관 엔진 방향표는 0으로 만들었다. 검증된 모델의 상승표가 계속 살아 있는 테스트도 작성했다. 앞으로도 모델이 기술지표만으로 학습됐다는 사실과 독립적인 예측력 검증 여부를 구분하고, 단순한 입력 중복을 모델 이름으로 정당화하지 않아야 한다.

8. **규칙 갱신을 예측의 일부로 검증한다 — 적용.** 손실 조건 제외 규칙이 바뀌었는데 프로세스가 이전 사본을 읽으면, 같은 종목과 시점에서도 서버에 따라 결과가 달라질 수 있다. 갱신 직후 재독과 파일 토큰 보강으로 정상적인 활성화 과정의 지연을 줄였다. 안정된 대형 아티팩트는 캐시를 사용해 반복 JSON 파싱 비용을 유지한다. 향후에는 원자적 파일 교체와 규칙 버전 식별자를 표준 배포 계약으로 묶으면 더 강한 추적이 가능하다. 이번에는 타임스탬프를 의도적으로 유지한 최근 덮어쓰기 사례를 재현했다.

9. **자료 부족과 부정적 평가를 다르게 표현한다 — 적용.** 비교할 표본이 없다는 것은 성과가 0이라는 뜻이 아니다. 보정 확률이 없고 손익분기 구조 비교도 불가능한 경우에는 ‘비교 자료 부족’으로 표시한다. 이미 정보용으로만 사용하기로 한 구조 점수에 ‘실행 보류’라는 문구를 붙이는 것도 제거했다. 이렇게 해야 규칙의 실제 차단 여부와 화면 설명이 일치한다. 향후 신뢰도·목표가·뉴스 품질에서도 null을 수치 0으로 바꾸는 경로를 공통적으로 검사할 필요가 있다.

10. **정확도는 커버리지·시점·비용과 함께 평가한다 — 후속 검증 기준.** 대기 신호를 늘리면 통과한 일부 사례의 적중률만 높게 보일 수 있다. 그러므로 전체 후보 수, 승인 수, 승인하지 않은 이유, 독립 검증 기간, 거래비용 후 결과를 동시에 저장해야 한다. 이번 과거 비교는 조건 정합성 감사이며 모델 성능 인증으로 사용하지 않는다. 향후에는 미사용 기간과 종목 집합에서 같은 정책을 고정하고, 시장별 비용 및 시점별 모델 버전을 보존한 재생으로 실효성을 확인해야 한다. 현재 부족한 데이터와 검증 범위를 공개한 상태에서 다음 실험을 설계한다.
